# OFDM Transmitter (TX) — RTL design + verification

SIM-ONLY TX that mirrors the validated RX (FFT→CE→EQ→16-QAM demod,
BER=0 on silicon).  It reproduces, bit-faithfully, the golden sync-capable
frame `golden/rx_downstream/tx_slot_iq_4032.hex` and closes the loop:
**TX RTL → `rx_downstream_top` → demod = BER 0 / 10608**.

Source of truth: `ref/transmitter.c`, the numpy model `scripts/rx_downstream_ref.py`
(`tx_modulate_block`), and `golden/rx_downstream/CONTRACT.md`.

## Numerology / fixed-point (CONTRACT.md)
NSC=256, CP=32, symbol=288, 2 sync + 12 data = 4032 slot.  32 QPSK pilots
(`pltIndx=1+8i`), 221 16-QAM data carriers (`dataIndx`), DC(128) + bins 0/255
zero.  Packing `{Q[31:16], I[15:0]}` Q15, scale **5090.697374** (RMS-matched
to fc_kp0).  16-QAM map `{-1,-3,+1,+3}·SCALE_16QAM` → Q15 `{-1610,-4829,+1610,+4829}`,
QPSK `±SCALE_QPSK` → `±3600`.

## Modules (new; no RX module modified)
| File | Role |
|---|---|
| `rtl/tx_subcarrier_map.v` | 16-QAM map + QPSK pilot insert + subcarrier assembly + fftshift → 256 spectrum bins (fftshift order), 1 bin/clk. Table-driven by `rtl/tx_rom/tx_specmap.hex`. Pilots addressed by index (fftshift walk is not index order). |
| `rtl/tx_ifft_frontend.v` | 256-pt IDFT via **xfft_N driven INVERSE** (config `8'h00`), BFP recover `(out16<<blk_exp)>>4` (= `1/√256`), then CP insert (prepend last 32 body samples) → 288-sample symbol. Double-buffered, 1 sample/clk. |
| `rtl/tx_ofdm_top.v` | Sequences 576 sync-ROM samples (REAL PSS/SSS, byte-identical to fc_kp0) + 12 data symbols through map→ifft → 4032-sample slot. |

IFFT IP choice: `xfft_N` is the only 256-pt 16-bit xfft IP; it is a
fixed-length BFP streaming core, so the same instance config runs inverse
(`FWD_INV=0`). `xfft_IFFT`/`xfft_2N` are 512-pt and not usable for the
256-pt IDFT.  This is a THIRD independent `xfft_N` instance (Meyr core owns
one, `rx_fft_frontend` the second).

## ROMs / golden (generated by `scripts/gen_tx_roms.py`)
- `rtl/tx_rom/tx_specmap.hex` — 256×12-bit `{src<<2|kind}` (3 zero, 32 pilot, 221 data).
- `rtl/tx_rom/tx_sync_rom.hex` — 576 sync samples (= golden frame [64:640]).
- `golden/tx/{tx_spec_in,tx_dsym_out,tx_slot_4032}.hex`, `tx_data_bits.txt`.

## Timing (OOC synth, `scripts/ooc_synth_tx.tcl`, part `xczu49dr-ffvf1760-2-e`, xfft_N black-boxed)
| Module | WNS @400 MHz | Fmax |
|---|---|---|
| `tx_subcarrier_map` | +1.788 ns | ~1404 MHz |
| `tx_ifft_frontend` | +0.092 ns | ~415 MHz |
| `tx_ofdm_top` | +0.116 ns | ~419 MHz |

All wrapper logic closes well above 400 MHz; the practical limit is the
xfft_N IP itself (>300 MHz OOC on this part), not the TX wrapper. 1 complex
sample/clock throughout (no rate change).

BFP truncation in the IFFT IP gives ≤ 3 LSB error vs the Q15 golden (the
Python model predicted ≤ 2 LSB); well inside the fixed-point budget and the
demod slicing margin (loop BER 0).  An iverilog inverse stub
(`tb/xfft_N_ifft_bfp_stub.v`) is provided for IP-free sanity only — the real
IP under xsim is the acceptance gate.
