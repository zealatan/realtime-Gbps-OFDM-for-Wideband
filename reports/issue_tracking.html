complex_mult_iq: s_axis_tready hardwired 1'b1 — ignores m_axis_tready — SSS path deadlock

Description
complex_mult_iq.v lines 44-45 unconditionally assert s_axis_a_tready and s_axis_b_tready as 1'b1, permanently ignoring the downstream m_axis_tready signal. The output register is overwritten every clock cycle regardless of whether downstream has consumed the previous value. This violates the AXI-Stream handshake specification (tvalid must not de-assert once asserted until tready is seen; tready backpressure must propagate upstream).
Root Cause
// complex_mult_iq.v lines 44-45 — THE BUG
assign s_axis_a_tready = 1'b1;   // ignores m_axis_tready
assign s_axis_b_tready = 1'b1;   // ignores m_axis_tready

// Output register overwrites unconditionally — no backpressure gate
always @(posedge aclk) begin
    if (!aresetn) begin
        m_axis_tvalid <= 1'b0;
    end else begin
        m_axis_tvalid <= s_axis_a_tvalid && s_axis_b_tvalid;  // ALWAYS updates
        m_axis_tlast  <= s_axis_a_tlast  && s_axis_b_tvalid;
        m_axis_tdata  <= {out_Q_shifted[COMPONENT_WIDTH-1:0],
                          out_I_shifted[COMPONENT_WIDTH-1:0]};
    end
end
Causal Chain (session_E SSS Deadlock)
complex_mult_iq.s_axis_a_tready = 1'b1 (hardwired, line 44)
→ corr_tready = 1 always in frac_cfo_corrector_top (s_axis_iq_tready = corr module's tready)
→ corr_accept = play_hold_valid && corr_tready = play_hold_valid — never waits
→ can_issue in frac_cfo_frame_corrector_top fires continuously, regardless of extractor stall
→ All 576 frac-corrected samples blasted in ~1152 cycles; extractor stalls at SSS sample 320 (hold_valid=1 while DFS processes PSS)
→ Samples 321-575 silently dropped (s_axis_tvalid=1 but extractor tready=0, upstream ignores it)
→ frac_cfo_frame_corrector_top enters S_DONE with no more output
→ DFS SSS_FILL: accepts sample 320 (in_cnt=0), then s_valid=0 permanently → deadlock
→ INTEGRATION_GATE: FAIL (session_E / p3_16a)

Planned Fix

complex_mult_iq.v — backpressure-capable ready logic

// Replace lines 44-45:
// OLD (broken):
//   assign s_axis_a_tready = 1'b1;
//   assign s_axis_b_tready = 1'b1;

// NEW (correct AXI-Stream):
assign s_axis_a_tready = !m_axis_tvalid || m_axis_tready;
assign s_axis_b_tready = s_axis_a_tready;

// Gate output register on backpressure:
always @(posedge aclk) begin
    if (!aresetn) begin
        m_axis_tvalid <= 1'b0;
        m_axis_tlast  <= 1'b0;
        m_axis_tdata  <= {DATA_WIDTH{1'b0}};
    end else if (s_axis_a_tready) begin  // only advance when upstream can be consumed
        m_axis_tvalid <= s_axis_a_tvalid && s_axis_b_tvalid;
        m_axis_tlast  <= s_axis_a_tlast  && s_axis_b_tvalid;
        m_axis_tdata  <= {out_Q_shifted[COMPONENT_WIDTH-1:0],
                          out_I_shifted[COMPONENT_WIDTH-1:0]};
    end
    // else: hold m_axis_tvalid/tdata until downstream is ready
end

nco_phase_gen.v — gate phase accumulation on backpressure

// Add input: s_axis_tready (from complex_mult_iq after fix)
// Gate phase_acc advance:
always @(posedge aclk) begin
    if (!aresetn)
        phase_acc <= 0;
    else if (s_axis_tvalid && s_axis_tready)  // only advance when sample consumed
        phase_acc <= phase_acc + phase_inc;
end

Complication: NCO currently runs free-running (independent of backpressure). After the multiplier fix, if NCO is not also gated, on resume from stall the phase offset will be wrong — producing incorrect frac CFO correction for samples after the stall point. The NCO must only advance when a sample is actually consumed (s_axis_tready=1 in the new logic).

ISSUE-002 MEDIUM RESOLVED Opened: 2026-06-01  |  Closed: 2026-06-03

session_D4: random equivalence failures — RESOLVED: testbench AXI-S race condition in stimulus feed loop

Description
The random equivalence gate (P3-15D, 100 pseudo-random parameter combinations) failed for 1 case (case_087). All failures clustered in the D2 comparison stage (slot metadata: slot_start, frac_cfo), producing a wrong peak_lag=133 instead of the expected ~20.

Root Cause (confirmed 2026-06-03): The AXI-Stream stimulus feed loop in tb/session_D3_p3_15c_equiv_tb.sv had a Verilog race condition. Each loop iteration did @(posedge aclk) followed by a blocking assign to s_axis_tdata — both the testbench update and the DUT's always @(posedge aclk) fired at the same simulation time. The non-deterministic event ordering caused s_axis_tdata to sometimes be sampled BEFORE the testbench updated it (DUT-first) and sometimes AFTER (TB-first), producing an alternating skip/duplicate pattern: every even-indexed stim sample was skipped and every odd-indexed sample was written twice to the iq_frame_buffer. This corrupted the IQ data seen by timing_sync_top, causing the Schmidl-Cox autocorrelation to find a spurious peak at lag=133 (metric=136) instead of the true peak at lag=23 (metric=151).

Fix: Added #1 after each @(posedge aclk) in the stimulus loop, placing all s_axis_tdata assignments strictly 1 ns after the rising edge. The DUT samples the stable data from the previous iteration; no race, no skip/duplicate.

Hypotheses

  2. Comparison tolerance: The equivalence script applies a strict equality check on frac_cfo; floating-point rounding in C reference vs. Q1.15 fixed-point in RTL may cause 1-LSB discrepancies that accumulate.

Note: D3 always passes, so the RTL correction arithmetic itself is not the bug — only the metadata derivation (D2) is affected.

DOC-001 COVERAGE GAP

Stage 4: No gate for PSS/SSS extraction boundary comparison vs C reference

Finding
No verification gate explicitly compares the pss_sss_symbol_extractor.v output sample-by-sample against C reference array offsets:
  • PSS: rxI[slotStart + CP_LEN .. slotStart + CP_LEN + NSC − 1] (indices 32..287)
  • SSS: rxI[slotStart + 2×CP_LEN + NSC .. slotStart + FRAME_LEN − 1] (indices 320..575)
The extractor output is validated only indirectly through the Meyr integer CFO result (P3-15A). A ±1 sample boundary error in extraction would not surface until the Meyr peak shifts.
Recommended Action
Add a new gate that feeds a known stimulus, runs pss_sss_symbol_extractor.v in isolation, and compares PSS output samples against ref/receiver.c:516 and SSS output against ref/receiver.c:519.

"STEP 31 LIMITATION: term2 is a synthetic XOR-shift32 PRNG ROM (seed 32'hCAFE_B0BB). The testbench mirrors the same sequence. Replace with the real mU/goldU-derived ROM in Step 32."

term2[j] = mU[j+CP_LEN] × conj(goldU[j+CP_LEN]) (receiver.c:527–528, with Nid_1=170, Nid_2=2).

If the testbench uses the same synthetic PRNG as the RTL, gates will pass even with incorrect ROM values.

HIGH if ROM files contain synthetic data; LOW if ROM files are confirmed as C-reference-derived. Session_J sweep (k_int=±8) passes, which is consistent with correct ROM values, but does not prove ROM correctness across the full subcarrier range.

1. Regenerate vectors/meyr_pss_reference_romhex.txt and vectors/meyr_sss_reference_romhex.txt from the C reference using m_seq() + gold_seq() (Nid_2=2, Nid_1=170).
