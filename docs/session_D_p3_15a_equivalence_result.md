## Known Issues / Observations

### Meyr Peak Index Off-by-One (Session B / pipeline integration)

**Observation:** When running through `phase3_sync_axis_dma_wrapper`, the Meyr estimator
reports `dut_meyr_peak_index = 256` and `dut_int_cfo_word = -16777216 = -2^24`.

**Expected:** For zero-CFO stimulus, peak should be at index 255 and step_word = 0.

**Verification:** Session A (probing `phase3_sync_top` directly) reports `RTL_MEYR_PEAK_INDEX 255`
and `RTL_INTEGER_CFO_WORD 0` — consistent with expected values.

**Root cause:** Discrepancy between direct probe (Session A) and wrapper probe (Session D).
May be related to:
- Pipeline register delay in the wrapper's debug path
- AXI-Lite register convention (INT_CFO_INDEX=256 also reported by Session C TB)
- Meyr estimator peak index convention (0-based vs 1-based FFT output)

**Impact on current gate:** None — ±1 tolerance applied to int_cfo_index and int_cfo_est_bins.

**Resolution:** Session B (real FFT / xsim validation) should clarify the correct peak index
convention and confirm whether the off-by-one is in the estimator or the reporting path.

### Frame Index / Slot Start ±1 Offset

**Observation:** frame_index=40 (expected 41), slot_start=63 (expected 64) from the wrapper probe.

**Root cause:** The hierarchical probe always block reads `dut_frame_start_index` at the posedge
where `dut_frame_start_valid=1`. Since this is a registered-output combinatorial chain, the
sampling may be off by one pipeline stage relative to the direct `phase3_sync_top` probe in Session A.

**Impact:** Within ±1 tolerance — passes Stage 2.

## P3-15B Resolution

Stages 4/5 unblocked by P3-15B without requiring external Session B/C provision:

### How Stage 4/5 was unblocked

The C golden IQ was generated using the Session D software NCO model:
1. RTL frac-corrected IQ captured from `dbg_frac_m` bus → `rtl_frac_iq.txt`
   (TB addition: `always @(posedge aclk) if (dbg_frac_m_tvalid && dbg_frac_m_tready)`)
2. step_word read from AXI-Lite register `INT_CFO_STEP_WORD` = 0xFF000000
3. `gen_c_m_axis_iq_golden.py` applies identical NCO arithmetic → `c_m_axis_iq_golden.txt`
4. 576/576 samples match RTL M_AXIS within ±1 LSB

### Known discrepancy (documented, not a defect)

The int_cfo step_word applied by the wrapper is 0xFF000000 (−k=+1) rather than 0 (k=0).
This is the wrapper's ±1 peak detection offset (confirmed by Session B P3-13C: direct
probe to phase3_sync_top gives peak=255, int_cfo=0 for k_int=0 stimulus).
Stage 3 passes with ±1 tolerance; Stage 5 is verified against the ACTUAL step_word used,
not the theoretically correct one.
