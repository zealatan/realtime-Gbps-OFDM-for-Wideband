7. Operation

Startup (S_IDLE)

On start pulse: busy_r=1, pss_fill_cnt=0, sss_cnt=0, fft_start_r=1 (1-cycle pulse to u_fft), state=S_FILL_PSS. The fft_start_r pulse triggers u_fft to begin its PSS fill phase.

S_FILL_PSS: Buffer PSS FFT Bins

The FSM accepts PSS FFT output bins from u_fft. fft_m_ready_r = !fft_m_symbol_sel || !fft_m_valid in S_FILL_PSS: this accepts PSS bins (sel=0) and stalls SSS bins (sel=1, stalling by not asserting ready). However, since u_fft streams PSS bins first and SSS bins only after all PSS bins are output, SSS bins cannot arrive during S_FILL_PSS in normal operation. The stall is a defensive guard.

Each accepted PSS bin is written: pss_fft_buf_i[fft_m_index] <= fft_m_i and similarly for Q. pss_fill_cnt increments on each write. At pss_fill_cnt==FFT_LEN (=256): state=S_START_EST. Note: the transition condition is pss_fill_cnt==FFT_LEN not 255, because pss_fill_cnt increments to 256 then the comparison triggers. The guard if (pss_fill_cnt < FFT_LEN) prevents overflow.

S_START_EST: Launch Estimator

est_start_r=1 (1-cycle pulse to u_est), state=S_STREAM_SSS. This fires the estimator start exactly one cycle before SSS bin streaming begins. The estimator enters its S_LOAD state next clock, ready to accept term1 samples.

S_STREAM_SSS: Pair PSS/SSS Bins and Feed Estimator

The key pairing logic: est_s_valid = (state==S_STREAM_SSS) && fft_m_valid && (fft_m_symbol_sel==1). When a live SSS bin arrives from u_fft, the estimator simultaneously receives:

  • pss_i = pss_fft_buf_i[fft_m_index] — buffered PSS bin at same index j
  • pss_q = pss_fft_buf_q[fft_m_index]
  • sss_i = fft_m_i — live SSS bin
  • sss_q = fft_m_q
  • s_index = fft_m_index — bin address j

fft_m_ready_r = est_s_ready in S_STREAM_SSS: the estimator's backpressure controls when SSS bins are consumed. sss_cnt increments on each accepted pair. At sss_cnt==FFT_LEN: state=S_WAIT_EST.

S_WAIT_EST: Wait for Estimator Completion

Polls est_done. When est_done fires, the results are captured: int_cfo_r=est_int_cfo, peak_index_r=est_peak_index, peak_score_r=est_peak_score. State=S_DONE. The estimator runs the full correlation (511 lags × up to 256 MAC operations each) during this wait period.

S_DONE

done_r=1, busy_r=0, state=S_IDLE. 1-cycle state.

Error Propagation

The top module sets error_r when: (1) start while busy, (2) fft_error asserts from u_fft, (3) est_error asserts from u_est. All three conditions are checked outside the FSM case statement on every clock, ensuring first-error capture with sticky behavior.

10. Algorithm Mapping

This module implements the cross-product term generation for the Meyr integer CFO estimator. In the C reference, fft_correlation_Meyr() (or equivalent) computes term1[j] = PSS_FFT[j] * conj(SSS_FFT[j]) for j=0..NSC-1, then correlates term1 with a reference sequence term2.

15. Known Issues and Lessons Learned

ISSUE-001 (complex_mult_iq backpressure): RESOLVED — affected earlier product_gen sub-module. This module correctly handles est_s_ready backpressure in S_STREAM_SSS by gating fft_m_ready_r = est_s_ready.
ISSUE-002 (TB AXI-S race, #1 fix): RESOLVED — testbench timing. This module was not directly affected once the TB was corrected.
XIP-003 lesson (FFT IP reset): The root cause of the 9/9 failures before FLUSH_COUNT=1 fix was in fft256_dual_symbol_frontend (u_fft), but the consequence manifested here as S_WAIT_EST hanging indefinitely because est_done never fired (estimator never received valid SSS data). Always test XIP-003 re-run after any aresetn sequence change.
ROM parameter plumbing bug: An earlier version of this module did not thread PSS_ROM_FILE and SSS_ROM_FILE parameters to the u_est instantiation (meyr_integer_cfo_freq_estimator_top), which in turn did not thread them to meyr_integer_cfo_core. Result: the core loaded zeros for term2 ROM, producing all-zero scores and a random peak index. Fix: explicitly pass PSS_ROM_FILE and SSS_ROM_FILE through the full parameter chain. Verification: DOC-003 confirmed 512/512 non-zero ROM entries loaded correctly.
S_FILL_PSS pss_fill_cnt comparison: The condition is pss_fill_cnt==FFT_LEN (=256), not ==FFT_LEN-1 (=255). This is because pss_fill_cnt increments on each valid write, and the write at count=255 (the 256th bin) increments to 256 before the comparison fires. The guard if (pss_fill_cnt < FFT_LEN) prevents overflow beyond 256. Future engineers: this is intentional; do not change to ==255 or a timing bug will cause S_START_EST to fire one cycle early.

Reset Sequence

  1. Assert aresetn=0 for ≥16 cycles (flushes u_fft and u_est sub-modules).
  2. Release aresetn=1. Confirm state=S_IDLE, busy=0.
  3. Verify upstream pss_sss_symbol_extractor is reset and ready to stream.
  4. Pulse start=1 for 1 cycle. Confirm fft_start_r=1 within 1 cycle, state=S_FILL_PSS within 2 cycles.
  5. Monitor pss_fill_cnt increase as PSS FFT bins arrive from u_fft (after u_fft's fill+stream+cap phases).
  6. At pss_fill_cnt=256: confirm state=S_START_EST (1 cycle) then S_STREAM_SSS.
  7. Monitor est_s_valid during S_STREAM_SSS; confirm 256 valid beats.
  8. In S_WAIT_EST: monitor est_done from u_est; expect ~131k cycles.
  9. On done: read int_cfo via AXI-Lite register.

Hardware Risks

  • PSS buffer underflow: If u_fft streams fewer than 256 PSS bins (e.g., watchdog error), pss_fill_cnt will never reach 256 and the FSM will hang in S_FILL_PSS. Add ILA trigger on S_FILL_PSS duration > 5000 cycles.
  • Estimator never completes: If u_est receives corrupted term1 data (all zeros from ROM bug), it still completes but peak_score will be 0 and peak_index will be the first lag (random). Add ILA trigger on peak_score=0 as an error indicator.
  • int_cfo vs peak_index consistency: int_cfo should always equal peak_index - 255. Add a self-check assertion in simulation and read both signals via ILA on hardware.

17. Debug Checklist

  1. Confirm state=S_IDLE (0) and busy=0 after aresetn release.
  2. Confirm fft_start_r=1 for exactly 1 cycle after start pulse; state transitions to S_FILL_PSS.
  3. Confirm fft_m_ready_r=1 during S_FILL_PSS when fft_m_valid=1 and fft_m_symbol_sel=0.
  4. Monitor pss_fill_cnt: must reach 256 (not 255!) for S_FILL_PSS exit.
  5. Verify pss_fft_buf_i/q[j] contains non-zero values after S_FILL_PSS (read back via ILA or simulation).
  6. Confirm S_START_EST is exactly 1 cycle; est_start_r=1 for exactly 1 cycle.
  7. In S_STREAM_SSS: verify est_s_valid=1 for 256 cycles with est_s_ready=1.
  8. Confirm fft_m_index values during S_STREAM_SSS match pss_fft_buf lookup addresses (j=0..255).
  9. Confirm sss_cnt reaches 256 for S_WAIT_EST entry.
  10. In S_WAIT_EST: monitor u_est outputs; est_busy should be high until est_done.
  11. Verify est_done fires within the expected cycle budget (~131k cycles for 511 lags).
  12. Confirm int_cfo = peak_index - 255 after done pulse.
  13. Check peak_score > 0 (zero score indicates zero ROM or data corruption).
  14. Check error=0; if error=1: check which sub-module set it (u_fft.error or u_est.error).
  15. If stuck in S_FILL_PSS: u_fft not producing PSS bins — check u_fft state (should be in S_STREAM_PSS or S_PSS_CAP).
  16. If stuck in S_WAIT_EST beyond 500k cycles: u_est likely deadlocked — check u_est state and its sub-module states.

18. Review Notes

Non-Obvious Design Decisions

  • Why buffer PSS bins in this module (not in u_est): The Meyr estimator (u_est) expects to receive term1 = PSS_FFT[j] * conj(SSS_FFT[j]) as a pre-computed product. The product generation logic (meyr_pss_sss_product_gen) requires both PSS and SSS bins simultaneously at the same index j. Since u_fft streams PSS then SSS sequentially, this module must buffer PSS and present it alongside live SSS bins. The 256-entry PSS buffer is the minimum storage to enable simultaneous PSS/SSS presentation.
  • fft_m_ready_r combinatorial (not registered): Registering fft_m_ready_r would add 1 cycle of backpressure latency, potentially causing u_fft to output a bin before ready is asserted and dropping it. Combinatorial ready directly tracks the FSM state and fft_m_symbol_sel, ensuring immediate response to bin type changes.
  • pss_fill_cnt compared to FFT_LEN not FFT_LEN-1: Ensures the 256th PSS bin (index 255) is written to the buffer before the FSM advances. The write and the comparison happen in the same always block; using ==255 would transition one cycle before the last write completes.
  • S_START_EST as a dedicated 1-cycle state: Separating the estimator start pulse into its own state prevents any ambiguity about when est_start_r fires relative to SSS bin streaming. If combined with S_FILL_PSS exit, est_start_r might fire while the estimator is not yet ready or before fft_m_ready_r transitions to est_s_ready mode.
  • Results latched in S_WAIT_EST on est_done: int_cfo_r, peak_index_r, peak_score_r are latched when est_done fires, not in S_DONE. This is because est_done is 1 cycle and the S_WAIT_EST→S_DONE transition takes 1 cycle. Latching in the transition cycle ensures results are stable by the time done_r asserts.

Notes for Future Engineers

  • If the estimator is replaced with a different algorithm, the S_STREAM_SSS state must be updated to match the new term1 interface. The current interface passes {s_index, pss_i, pss_q, sss_i, sss_q} to u_est.
  • The module does not validate that fft_m_index covers all values 0..255. If u_fft skips a bin index (e.g., due to tuser corruption), pss_fft_buf[j] for that index will contain stale data from a previous run. This silent error would propagate to the correlation result. Add an ILA check: pss_fill_cnt should equal the number of unique fft_m_index values seen during S_FILL_PSS.
  • For NSC != 256: update FFT_LEN and INDEX_WIDTH parameters. pss_fill_cnt and sss_cnt are 9-bit — supports FFT_LEN up to 511. For FFT_LEN=512, widen to 10-bit.
