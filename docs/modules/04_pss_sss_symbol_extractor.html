7. Operation

Startup / Reset

On aresetn low: FSM resets to S_IDLE, all counters zero, hold_valid=0, busy/done/error=0. After reset release, the module waits for a start pulse.

S_IDLE Window Validation

On start pulse, the RTL validates the configured window parameters before entering S_STREAM. The validation checks: pss_fft_end ≤ frame_len, sss_fft_end ≤ frame_len, windows are not identical, and windows do not overlap. Any violation immediately transitions to S_ERROR with error_code=1. On success, all counters and the hold register are cleared, busy asserts, and the FSM enters S_STREAM.

S_STREAM Main Operation

The core loop: on each s_fire (s_valid && s_ready), frame_idx increments. Two combinatorial window comparators run continuously:

  • in_pss_window: asserts when !pss_done_r && frame_idx ≥ pss_fft_start && frame_idx < pss_fft_end
  • in_sss_window: asserts when !sss_done_r && frame_idx ≥ sss_fft_start && frame_idx < sss_fft_end

Out-of-window samples are consumed and discarded; s_axis_tready stays high since hold_valid is low. In-window samples are written into the hold register with the appropriate hold_sel (0=PSS, 1=SSS), hold_index (= pss_cnt or sss_cnt), and hold_tlast_r (= pss_last_sample or sss_last_sample). The window sample counters pss_cnt and sss_cnt increment on each captured sample.

Hold Register Backpressure

The module implements a 1-entry elastic buffer. s_axis_tready = !hold_valid in S_STREAM. When a new in-window sample arrives and the hold register is full, the module cannot accept it — but this cannot happen in practice because s_axis_tready was deasserted from the previous cycle (hold_valid was set). Each in-window sample acceptance simultaneously deasserts tready, guaranteeing the upstream stalls until downstream consumes the held output.

Key invariant: hold_valid is cleared whenever hold_valid && m_axis_tready fires, without regard to FSM state. This runs in parallel to the FSM case statement.

S_DONE State and Window Completion

The FSM transitions to S_DONE when both pss_done_r and sss_done_r are set (either currently or on the current s_fire). This can happen before s_axis_tlast or exactly at tlast. In S_DONE, s_axis_tready=1'b1 unconditionally — any remaining input samples are consumed and discarded, preventing upstream stall. The done pulse asserts one cycle after hold_valid drains to zero.

Error Handling

Three error conditions exist:

  • error_code=1: Window overlap or out-of-frame. Checked at start time in S_IDLE. FSM goes to S_ERROR immediately, never entering S_STREAM.
  • error_code=2: s_axis_tlast received before both windows are complete. Indicates upstream sent fewer than FRAME_LEN samples. Sets error, transitions to S_ERROR.
  • error_code=4: start pulse received while busy (in S_STREAM). Sets error but does not interrupt ongoing extraction.

S_ERROR is cleared only by a subsequent start pulse (which resets error and returns to S_IDLE), or by aresetn.

tlast Generation

m_axis_tlast (= hold_tlast_r) captures pss_last_sample or sss_last_sample at the time the last sample of each window is written to the hold register. This provides a frame-end signal to the downstream FFT frontend that precisely coincides with sample index 255.

15. Known Issues and Lessons Learned

ISSUE-001 (complex_mult_iq backpressure): RESOLVED — unrelated to this module but caused TB AXI-S races in early testing.
ISSUE-002 (TB AXI-S race, #1 delay fix): RESOLVED. The TB was driving m_axis_tready and s_axis_tvalid on the same clock edge as the DUT, causing setup violations. Fix: add `#1` delay after posedge in TB before asserting signals. This module's tready/tvalid logic was correct; the issue was pure testbench timing.
S_DONE drain is mandatory. Without it, when both windows complete before s_axis_tlast arrives, the upstream frac_cfo_frame_corrector_top output would see s_axis_tready=0 and stall. The frac corrector must emit all FRAME_LEN samples to de-assert busy and pulse done. Early versions omitted the drain, causing a deadlock: extractor waiting for nothing, frac corrector stalled mid-frame.
s_symbol_sel pre-set for SSS: the hold_sel field correctly uses in_sss_window priority over in_pss_window for the ternary assignment. In theory the PSS and SSS windows do not overlap (validated at start), but the priority ordering ensures SSS wins if both signals asserted simultaneously due to a bug in window configuration.
Error code=4 (start_while_busy) sets the error flag but does not interrupt ongoing extraction. The current operation continues to completion. This is intentional — aborting mid-extraction would leave partial data in the downstream FFT buffers.

Reset Sequence

  1. Assert aresetn=0 for at least 16 clock cycles.
  2. Release aresetn=1. Confirm state=S_IDLE, busy=0, done=0.
  3. Configure pss_fft_start = detected_frame_start + 32, sss_fft_start = detected_frame_start + 320, frame_len = 576 via AXI-Lite register writes.
  4. Confirm upstream frac_cfo_frame_corrector_top is idle and ready to stream.
  5. Pulse start=1 for one clock cycle.
  6. Observe state transition to S_STREAM within 1 cycle.
  7. Observe first m_axis_tvalid rising edge at frame_idx=32 (after 32 CP samples discarded).

Hardware Risks

  • Window misalignment: If frame_start_index from the correlation peak detector is wrong (off by 1 or more bins), the PSS/SSS windows will capture incorrect samples. Verify frame_start against known test patterns before running integer CFO estimation.
  • FRAME_LEN mismatch: If upstream frac corrector emits fewer than 576 samples (e.g., OUTPUT_SAMPLES parameter mismatch), error_code=2 will fire. Check pss_sss_symbol_extractor.frame_len AXI-Lite register matches OUTPUT_SAMPLES.
  • m_axis_tready stuck low: If downstream FFT frontend fails to assert m_ready, the extractor will stall mid-extraction, eventually stalling the full pipeline. Add ILA trigger on m_axis_tready=0 for >1000 cycles.

17. Debug Checklist

  1. Confirm aresetn releases correctly; verify state=S_IDLE after reset.
  2. Confirm pss_fft_start=frame_start+32, sss_fft_start=frame_start+320 are correct (read back AXI-Lite registers).
  3. Confirm frame_len=576 in the register; mismatch causes error_code=2.
  4. Verify start pulse is exactly 1 cycle wide and arrives in S_IDLE.
  5. Observe state transitions: IDLE→STREAM in 1 cycle after start.
  6. At frame_idx=32: verify in_pss_window=1, m_axis_tvalid rises within 1 cycle (after hold clears).
  7. Count m_axis_tvalid beats with m_symbol_sel=0 — expect exactly 256.
  8. Verify m_axis_tlast at m_symbol_index=255 for PSS (sel=0).
  9. After PSS tlast: verify m_symbol_sel switches to 1 at next m_axis_tvalid (SSS[0]).
  10. Count m_axis_tvalid beats with m_symbol_sel=1 — expect exactly 256.
  11. Verify done pulse asserts within 2 cycles after SSS m_axis_tlast.
  12. Check error flag and error_code if done does not pulse within 650 cycles of start.
  13. If error_code=2: count s_fire events; upstream likely sent fewer than 576 samples.
  14. Verify S_DONE drain: s_axis_tready=1 after last SSS sample, even before done pulse.

18. Review Notes

Non-Obvious Design Decisions

  • 1-entry hold register vs FIFO: A FIFO would add unnecessary area and complexity. The 1-entry register provides the minimum elastic buffering needed to tolerate 1-cycle backpressure between upstream (which may fire continuously) and downstream (which may stall 1 cycle). The design is statically verifiable: upstream stalls immediately when hold_valid=1, so no overflow is possible.
  • s_axis_tready = !hold_valid (not combinatorial from m_fire): This avoids a combinatorial loop through the upstream module's ready logic. hold_valid clears one cycle after m_fire, giving tready a registered path.
  • frame_idx does not reset to 0 at frame start: frame_idx is initialized to 0 on start (in S_IDLE branch), not on tlast. This is correct because the frac corrector emits exactly FRAME_LEN=576 samples starting at frame_idx=0 relative to the frame boundary. The window positions (pss_fft_start=32, sss_fft_start=320) are already absolute frame offsets.
  • pss_done_r / sss_done_r flags: These prevent re-triggering the window comparators after a window completes if a counter wrap bug were ever introduced. They also enable early S_DONE transition before s_axis_tlast.
  • S_ERROR requires explicit start to clear: This prevents the module from silently recovering and producing incorrect output. The parent state machine must observe the error, handle it (e.g., log, re-trigger correlation), and explicitly restart.
  • NSC_FI / NSC_LAST localparams: Vivado-safe workaround for the Verilog-2001 constraint that forbids SystemVerilog-style sized constants like FRAME_INDEX_WIDTH'(NSC). Always use these localparams when mixing parameter widths in arithmetic.

Notes for Future Engineers

  • If NSC changes from 256, update NSC parameter. NSC_W, NSC_FI, NSC_LAST, and all counters auto-size via $clog2 and parameterized widths.
  • The module does not buffer output — it is a streaming extractor. The 512 output samples arrive in order (PSS[0..255] then SSS[0..255]) with gaps between windows. Downstream must handle gaps (no valid output) between the PSS and SSS windows.
  • If future requirements add a third symbol window (e.g., PBCH), replicate the pss/sss cnt/done_r pattern for a third window and add a third output valid stream. The hold register logic extends naturally.
