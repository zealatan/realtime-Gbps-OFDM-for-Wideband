7. Operation

ROM Initialization (Simulation Elaboration)

At simulation elaboration (initial block), $readmemh loads PSS and SSS reference data into temporary packed arrays. The term2 ROM is then computed:

For j = 0..255:
  _pss_i_val = $signed(_pss_rom_packed[j][15:0]) -- PSS_ref I component (Q1.15)
  _pss_q_val = $signed(_pss_rom_packed[j][31:16]) -- PSS_ref Q component (Q1.15)
  _sss_i_val = $signed(_sss_rom_packed[j][15:0]) -- SSS_ref I component (sign only)
  if _sss_i_val ≥ 0: term2_i_rom[j] = +_pss_i_val; term2_q_rom[j] = +_pss_q_val
  if _sss_i_val < 0: term2_i_rom[j] = -_pss_i_val; term2_q_rom[j] = -_pss_q_val

term2[j] = PSS_ref[j] × sign(SSS_ref_I[j]) -- BPSK SSS modulation cancellation

This pre-computation matches the C reference formula for the Meyr CFO estimator where the SSS subcarrier sign (BPSK) is applied to the PSS reference to create a composite term2 sequence.

S_IDLE: Waiting for start

Module is idle, busy=0, done=0. start_while_busy guard active. On start: busy=1, load_cnt=0, state=S_LOAD.

S_LOAD: Receive 256 term1 Samples into RAM

term1_ready is high (combinatorial wire). On each term1 fire: term1_i_ram[term1_index] <= term1_i. load_cnt increments. When load_cnt == NSC-1 (=255): state=S_PD_START. Note: load_cnt is compared to NSC-1, not NSC, because the write happens simultaneously with the comparison — the 256th sample (index 255) triggers the transition on the same clock it is written.

S_PD_START: Initialize Correlation Loop

pd_start_r=1 (1-cycle pulse to peak_detector), lag_p=0, n_cnt=n_start_cur (for lag_p=0), n_end_r=n_end_cur (for lag_p=0), acc_i=0, acc_q=0, state=S_CORR.

For lag_p=0 (lag = -255): n_start_cur = 255-0 = 255, n_end_cur = 255. So only n=255 is accumulated for lag=0. This is correct: at lag=-255, only the overlap index n=255 produces a valid t1_idx=0.

S_CORR: One MAC Per Clock

The MAC computes one term per clock cycle:

t1_idx = n_cnt + lag_p - 255 (wire: t1_sum - 10'd255)
t1_i_w = term1_i_ram[t1_idx] (Q1.30 product of PSS_FFT[j]*conj(SSS_FFT[j]) I-part)
t2_i_w = term2_i_rom[n_cnt] (Q1.15 term2 reference at index n)

Scale: t1 >>= 16 to reduce Q1.30 to Q1.14 range before multiply with Q1.15 term2
mac_i_w = (t1_i_w >>> 16) * t2_i_w + (t1_q_w >>> 16) * t2_q_w -- real part of t1*conj(t2)
mac_q_w = (t1_q_w >>> 16) * t2_i_w - (t1_i_w >>> 16) * t2_q_w -- imag part

acc_i += sign_extend(mac_i_w, 56)
acc_q += sign_extend(mac_q_w, 56)

When n_cnt == n_end_r: state = S_LAG_END
Else: n_cnt += 1

The complex multiply formula (a+jb)(c-jd) = (ac+bd) + j(bc-ad) is the product of term1 with the conjugate of term2. This matches the C reference: corr[p] = sum_{n} term1[n+lag] * conj(term2[n]).

S_LAG_END: Score Current Lag, Advance to Next

Score computation:

si_s = acc_i[39:8] -- 32-bit significant slice (bits 39..8 of 56-bit accumulator)
sq_s = acc_q[39:8]
si_abs = |si_s|, sq_abs = |sq_s| (2's complement absolute value)
score_w = si_abs^2 + sq_abs^2 (64-bit: {32'd0, si_abs}^2 + {32'd0, sq_abs}^2)

pd_data_in_r = score_w
pd_data_valid_r = 1 (1-cycle)
pd_data_last_r = (lag_p == LAG_COUNT-1) -- last lag is lag_p=510

acc_i = 0; acc_q = 0 (reset for next lag)

If lag_p == LAG_COUNT-1: state = S_WAIT_PD
Else: lag_p++; n_cnt = n_start_nxt; n_end_r = n_end_nxt; state = S_CORR

The slice acc_i[39:8] corresponds to keeping bits with significant energy. For 256 terms of Q1.14 * Q1.15 = Q2.29 products, the accumulator max magnitude is approximately 256 * 2^29 = 2^37. Bits [39:8] represent a 32-bit window that captures this range with 2 bits of overflow headroom.

n_start / n_end for Each Lag

lag = lag_p - CENTER = lag_p - 255

If lag_p ≥ CENTER (lag ≥ 0): n_start = 0, n_end = NSC-1 - lag = 510 - lag_p
If lag_p < CENTER (lag < 0): n_start = -lag = 255-lag_p, n_end = NSC-1 = 255

Equivalently: overlap length = NSC - |lag| = 256 - |lag_p - 255|
At lag_p=0 (lag=-255): 1 term. At lag_p=255 (lag=0): 256 terms. At lag_p=510 (lag=+255): 1 term.

The n_start_nxt and n_end_nxt wires pre-compute values for lag_p+1, allowing simultaneous lag advancement in S_LAG_END without a stall cycle.

S_WAIT_PD: Wait for Peak Detector

Waits for pd_done from u_peak. On pd_done: peak_index=pd_peak_index, peak_score=pd_peak_value, int_cfo = $signed({7'b0, pd_peak_index}) - 16'sd255, state=S_DONE.

S_DONE

done=1, busy=0, state=S_IDLE. 1-cycle state.

10. Algorithm Mapping

This module implements the core of the Meyr integer CFO estimation algorithm. The C reference function carrierFreqOffsetEstMeyr() computes a cross-correlation between term1 (PSS_FFT[j]*conj(SSS_FFT[j])) and term2 (PSS_ref[j]*sign(SSS_ref_I[j])) over all lags.

m_seq() and gold_seq() Reference Mapping

The ROM content (term2) corresponds to the C functions m_seq() and gold_seq() which generate the 5G NR PSS Zadoff-Chu and SSS m-sequence/Gold-sequence reference symbols. The ROM was generated offline and stored in the hex files. The formula term2[j] = PSS_ref[j] * sign(SSS_ref_I[j]) combines both sequences so the correlation with term1 (PSS_FFT * conj(SSS_FFT)) produces a peak at the integer CFO lag.

15. Known Issues and Lessons Learned

ISSUE-001 (complex_mult_iq backpressure): RESOLVED — this core's term1_ready = (state==S_LOAD) is a clean backpressure signal. The upstream product_gen module must respect term1_ready; confirmed working in all test gates.
ISSUE-002 (TB AXI-S race, #1 fix): RESOLVED — the term1 input to this module is not a standard AXI-S interface with separate handshake timing. The term1_valid/ready protocol is simple; no AXI-S race issue here.
ROM parameter plumbing bug: RESOLVED (DOC-003). Root cause: PSS_ROM_FILE and SSS_ROM_FILE parameters were not propagated from phase3_sync_top through meyr_integer_cfo_fft_frontend_top through meyr_integer_cfo_freq_estimator_top to meyr_integer_cfo_core. Each instantiation used the module default ("vectors/...") which resolved correctly only when the simulation was run from the correct directory. The bug manifested as zeros in term2 ROM when run from a different directory. Fix: explicitly pass parameters at each instantiation level.
FLUSH_COUNT=1 lesson (XIP-003): This module was not the root cause of XIP-003 failures. The SSS fill deadlock was in fft256_dual_symbol_frontend. However, without correct SSS term1 data, the correlation here would produce random peak results regardless of correctness. The chain of fixes (aresetn between cases + FLUSH_COUNT=1 + ROM parameter threading) was needed for all 9/9 cases to pass.
acc[39:8] score slice: The choice of bits [39:8] was empirically validated against the C reference for the test stimulus (Q1.15 FFT outputs with SNR ~30 dB). For different signal levels (e.g., very strong or very weak signals), the peak score magnitude may shift outside this slice range. If peak_score appears abnormally small, check whether the accumulator saturates in the upper bits (check acc_i[55:40] is all-zero or all-one sign extension).
load_cnt compared to NSC-1 (not NSC): The S_LOAD exit condition is load_cnt==NSC-1 because load_cnt starts at 0 and increments on each write. When term1_index=255 arrives, load_cnt is at 255 (=NSC-1), triggering the transition while the 256th write occurs. This is correct and verified; do not change to NSC-1 termination to NSC or the last term1 sample will be missed.

Reset Sequence

  1. Assert aresetn=0 for ≥16 cycles. Resets FSM, accumulators, counters, and peak_detector sub-module.
  2. Release aresetn=1. Verify state=S_IDLE (0), busy=0, load_cnt=0.
  3. ROM data is initialized at elaboration (initial block); no runtime reload needed.
  4. Pulse start=1 for 1 cycle. Verify state=S_LOAD within 1 cycle, term1_ready=1.
  5. Stream 256 term1 pairs (term1_valid=1, term1_index=0..255, term1_i/q from product_gen).
  6. Monitor load_cnt increase; verify transition to S_PD_START at load_cnt=255.
  7. Monitor lag_p progress through S_CORR/S_LAG_END loop.
  8. Read int_cfo and peak_score registers after done pulse.

Hardware Risks

  • ROM file path: PSS_ROM_FILE and SSS_ROM_FILE paths are relative to the simulation working directory. For synthesis, Vivado uses a different working directory. Ensure ROM file paths in the synthesis project are absolute or correctly relative. ROM files must be present at synthesis time for $readmemh to execute in simulation; for synthesis, the ROM contents must be pre-loaded or converted to a BRAM initialization file.
  • DSP48 timing: The MAC uses 32-bit operands after the >>16 shift (16-bit effective). At high clock rates (>200 MHz), the 32×32-bit DSP48 chain may require pipeline register insertion. The current RTL uses combinatorial multiply (mac_i_w as wire); for high-frequency synthesis, pipeline registers may be needed, which would change the FSM timing.
  • peak_score = 0 on hardware: If peak_score is consistently 0 or very small, the most likely causes are: (1) term2 ROM contains zeros (parameter plumbing bug), (2) term1 data from upstream is all zeros (FFT or product_gen failure), (3) the acc[39:8] slice is in the wrong range for the actual signal levels.

17. Debug Checklist

  1. Confirm state=S_IDLE (0) and busy=0 after aresetn release.
  2. Pulse start and confirm state=S_LOAD within 1 cycle, term1_ready=1.
  3. Verify 256 term1 fire events (term1_valid && term1_ready=1) during S_LOAD; load_cnt must reach 255.
  4. Confirm S_PD_START is exactly 1 cycle; pd_start_r=1 during this cycle.
  5. At S_CORR entry: lag_p=0, n_cnt=255 (n_start for lag_p=0), n_end_r=255.
  6. Verify t1_idx = n_cnt + lag_p - 255 = 255 + 0 - 255 = 0 for first MAC. term1_i_ram[0] should be valid.
  7. Verify lag_p increments correctly: lag_p=0 (1 MAC), lag_p=1 (2 MAC), ..., lag_p=255 (256 MAC), ..., lag_p=510 (1 MAC).
  8. Confirm pd_data_valid_r pulses exactly 511 times (once per S_LAG_END).
  9. Verify pd_data_last_r=1 only at lag_p=510 (the 511th score).
  10. Monitor acc_i/q resets to 0 in S_PD_START and each S_LAG_END.
  11. At lag_p=peak_lag (expected int_cfo+255): confirm acc_i/q has maximum magnitude; pd_data_in_r has maximum score.
  12. Confirm pd_done fires within 5 cycles after last S_LAG_END.
  13. Confirm int_cfo = pd_peak_index - 255 after S_WAIT_PD.
  14. Check peak_score > 0; if zero: read term2_i_rom[0] via simulation to confirm ROM loaded.
  15. If stuck in S_LOAD: verify term1_valid=1 from upstream and term1_index increments 0..255.
  16. If stuck in S_CORR indefinitely: check n_end_r is being set correctly for current lag_p; add ILA on n_cnt vs n_end_r.
  17. If int_cfo is wrong by a constant offset: check CENTER=255 parameter; verify PSS_ROM_FILE and SSS_ROM_FILE are the correct reference sequences.

18. Review Notes

Non-Obvious Design Decisions

  • term2 = PSS * sign(SSS_I) (not PSS * SSS): The Meyr algorithm exploits the fact that the SSS uses BPSK modulation (sign = ±1 per subcarrier). By dividing by the SSS sign, the product term1[j] = PSS_FFT[j] * conj(SSS_FFT[j]) cancels the BPSK modulation, leaving only the CFO-dependent phase shift. The correlation peak aligns at the integer CFO lag regardless of the SSS sequence content.
  • t1_idx = n_cnt + lag_p - CENTER: This maps the (lag, n) coordinates to a RAM address. For lag ≥ 0 (lag_p ≥ 255): n ranges 0..NSC-1-lag, and t1_idx = n + lag (offset from zero). For lag < 0: n ranges -lag..NSC-1, and t1_idx = n + lag (still a valid 0..NSC-1 address). The formula ensures t1_idx always falls in [0..255] for valid (lag_p, n_cnt) combinations. This is verified by the n_start/n_end constraints.
  • Score using acc[39:8], not full acc: Full 56-bit squaring would require 112-bit arithmetic for the score. The [39:8] slice trades precision for implementation simplicity. The 32-bit slice has ~8 bits of signal-to-quantization margin for the expected accumulator magnitudes. The peak is clearly distinguishable even with this truncation (J1 sweep: 13/13 correct detections).
  • No circular correlation: The correlation is linear (not circular). This matches the C reference which uses linear cross-correlation to estimate the integer frequency offset. Circular correlation would mix lag=+N with lag=0, which would corrupt the CFO estimate for large integer offsets.
  • Online argmax via peak_detector: Scores are fed to peak_detector one at a time as they are computed. This avoids storing all 511 scores simultaneously (which would require a 511-deep BRAM). The peak_detector maintains a running maximum with O(1) memory.
  • n_end_nxt / n_start_nxt pre-computation: These wires compute the next lag's n boundaries in the same clock as S_LAG_END, eliminating a stall cycle that would otherwise occur when advancing lag_p. The forward-looking computation is based on lag_p+1 = lag_p_nxt.

Notes for Future Engineers

  • The ROM initialization uses Verilog initial blocks and $readmemh. These are simulation constructs. For FPGA synthesis, the ROMs must be implemented either as: (a) BRAM with .coe initialization files, (b) distributed LUT ROM using generate blocks with explicit case statements, or (c) external AXI-Lite write interface. The current RTL is simulation-valid; synthesis needs attention for ROM loading.
  • Increasing NSC beyond 256 requires widening: n_cnt (8-bit), load_cnt (8-bit, compare to NSC-1), lag_p (INDEX_WIDTH must cover 2*NSC-1). Also update n_end_cur_9 wire (currently 9-bit for 9'd510). If NSC=512: lag_p needs 10-bit, n_cnt needs 9-bit.
  • The MAC scale factor (>>16) was chosen empirically. For different data pipelines (e.g., 12-bit FFT output instead of 16-bit), recalculate the scale: term1 would be Q2.22 (product of two Q1.11), term2 Q1.11. Adjust the >> shift accordingly to keep the product within PROD_WIDTH=32 bits.
  • peak_detector accepts max_count=0 (no count limit) and terminates on data_last=1. If LAG_COUNT changes, no peak_detector parameter update is needed — it automatically terminates when data_last fires at lag_p=LAG_COUNT-1.
