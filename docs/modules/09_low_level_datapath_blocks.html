2. Integration Context

The 14 primitives in this document constitute the leaf nodes of the RTL hierarchy. They are instantiated inside the mid-level wrappers (frac_cfo_frame_corrector_top, meyr_integer_cfo_core, fft256_dual_symbol_frontend, pss_sss_symbol_extractor, etc.) which in turn feed into phase3_sync_top and ultimately phase3_sync_axis_dma_wrapper.

All modules share a common AXI4-Stream IQ packing convention: tdata[15:0] = I, tdata[31:16] = Q, Q1.15 fixed-point. Backpressure follows the standard valid/ready handshake. The sole exception is fft256_xilinx_wrapper with C_THROTTLE_SCHEME=0 (no output tready on the Xilinx IP).

  • sample_power_sq — combinatorial I²+Q²

A.2 Operation

The wrapper FSM orchestrates a memory-mapped scan over search_len samples starting at search_base in the replay buffer. Each sample costs 2 wrapper clocks: S_FETCH issues the registered buffer read; S_PROC drives sample_valid high with the returned data. Combinatorial block sample_power_sq computes I²+Q² in the same clock. sliding_window_sum maintains a rolling CP_LEN-sized energy window; frame_detect_fsm counts consecutive windows exceeding thresh_mult = threshold_in × window_len_in.

On early termination (fsm_frame_found_w asserted mid-scan), the wrapper exits immediately to S_DONE. After the last sample, S_DRAIN holds for 6 clocks to flush the 2-stage SWS→FSM pipeline before declaring the result.

Legacy Primitives Used

  • moving_avg_optimized — CP_LEN sliding sum (×3)
  • sample_power_sq — 2-cycle |x|²
  • complex_to_mag — alpha-max/beta-min (debug only)

B.2 Operation

Implements the Schmidl-Cox CP autocorrelation (also known as VanDeBeek): for each input sample n, accumulates the sliding sum of conj(r[n-NSC]) × r[n] over a CP_LEN-sample window. The delay_sample RAM provides the NSC=256 sample delay. A parallel energy path computes |r[n]|² and accumulates it with the same window size, aligned by a 2-cycle padding stage to match the complex_mult latency.

Convention mismatch: legacy complex_mult expects I in the upper half but Phase2 packs I in the lower half. The wiring compensates: cm_a_i = delayed[15:0], cm_a_q = -delayed[31:16] (conjugate), etc.

B.3 Pipeline

delay_sample (1 cy) → complex_mult (3 cy) → moving_avg (4 cy) = 8 cy total (P path)
sample_power_sq (2 cy) + 2 cy align-delay → moving_avg (4 cy) = 8 cy total (E path)

B.4 Algorithm Mapping

P[n] = Σk=0CP_LEN-1 conj(r[n+k]) × r[n+k+NSC]
E[n] = Σk=0CP_LEN-1 |r[n+k+NSC]|²
C ref: VanDeBeekAutoCorrelation() / auto_corr() in ref/receiver.c

B.5 Latency / Throughput

  • 1 sample/clock input rate (s_valid=1 every cycle)
  • Out_valid latches permanently after first window (NSC+CP_LEN+8 ~296 cycles)
  • P and E outputs update every clock once valid

B.6 Resource Impact

  • delay_sample: 256×32b = 8 Kb — 1×BRAM18 or deep LUTRAM
  • 3×moving_avg_optimized: 3 small BRAMs or SRL shift registers
  • complex_mult: ~4 DSP48 slices

C.2 Operation

Drives a sequential read address from lag=0 to lag=num_lags-1. On each cycle the combinatorial metric is computed from the zero-latency autocorr read port. The metric uses a squared Cauchy-Schwarz form to avoid magnitude-approximation ordering errors:

sq_neg = E_s² − 4×(P_I_s² + P_Q_s²) ≥ 0 (always, by Cauchy-Schwarz)
metric_out = ~sq_neg[58:27] ← invert so peak_detector MAX finds minimum sq_neg
Correct lag: sq_neg ≈ 0 → metric_out ≈ 0xFFFFFFFF

ROM Design

  • 256-entry LUT: index = phase_acc[31:24] (8 MSBs)
  • Full 2π cycle; 0x40→90°, 0x80→180°
  • Convention: 0x7FFF=+1.0, 0x0000=0, 0x8001=−1.0

H.2 Operation

Phase accumulator phase_acc_r increments by step_word_r every enabled clock. The 8 MSBs index the ROM; the ROM output propagates through a LATENCY=15 register pipeline followed by a final output register, yielding 16 total cycles of latency. When enable=0 the entire pipeline (including phase_acc_r) freezes, keeping NCO phase aligned to accepted AXI-S samples.

enable is driven as enable && s_axis_iq_tready from frac_cfo_corrector_top, ensuring NCO phase does not advance when downstream is stalled.

K.2 Operation

A generate block selects among four modes. In synthesis (USE_BEHAVIORAL_STUB=0) the actual Xilinx xfft_v9_1_8 IP is instantiated. The config channel is driven continuously (tvalid=1) after reset deasserts; the IP latches the config word at the accepted handshake before each frame. C_HAS_ARESETN=0: the underlying IP has NO reset port. The wrapper must be reset between FFT frames by managing the config state machine. Lesson XIP-003: do_reset() must be called per frame case to avoid config state machine lockout.

L.2 Operation

Two-clock pipeline: inputs registered in stage 1; products computed combinatorially from registered values; outputs registered in stage 2. A 33-bit intermediate (t1_i_full = {prd_ac[31],prd_ac} + {prd_bd[31],prd_bd}) avoids overflow when summing two 32-bit products of 16-bit operands. Backpressure: s_ready = !m_valid || m_ready (natural pipeline backpressure).

L.3 Algorithm Mapping

term1_i = PSS_I×SSS_I + PSS_Q×SSS_Q
term1_q = PSS_Q×SSS_I − PSS_I×SSS_Q

C ref (receiver.c lines 523-525):
crossCorrTerm1I[j] = signalPSSfftI[j]*signalSSSfftI[j] + signalPSSfftQ[j]*signalSSSfftQ[j]
crossCorrTerm1Q[j] = −signalPSSfftI[j]*signalSSSfftQ[j] + signalPSSfftQ[j]*signalSSSfftI[j]

L.4 Latency / Throughput

  • 2-clock pipeline latency (input reg → output reg)
  • 1 sample/clock throughput when m_ready=1

L.5 Resource Impact

  • 4×16×16 multipliers: ~4 DSP48 slices
  • Two 33-bit adders; output registers: 2×32b + 8b index + 1b valid

N.3 Snapshot Protocol

1. frame_start_valid_i fires → 5 result fields latched into live registers
2. SW reads 0x38 (INT_CFO_VALID) while latch=1
3. → 5 shadow registers frozen simultaneously (frame_index, peak_index, slot_start, frac_cfo, int_cfo_word)
4. Reads of 0x1C/0x20/0x24/0x2C/0x3C return shadow values until snapshot_valid clears
5. snapshot_valid clears when SW reads 0x38 again or when next int_cfo_valid fires

N.4 Resource Impact

  • 21 control/status registers: ~256 flip-flops
  • 5 snapshot shadow registers: ~100 flip-flops
  • AXI4-Lite FSM: ~10 flip-flops
  • ADDR_WIDTH=7 (128-byte address space)

XIP-003 Lesson — FFT Reset Between Frames

Lesson: fft256_xilinx_wrapper config state machine must be reset (do_reset() called) between FFT frames. Failure to reset causes config SM lockout where IP never accepts new config, stalling the input channel indefinitely.

Lessons Learned Summary

  • Always include !m_axis_tvalid guard in AXI-S can_accept logic for registered pipelines
  • TB timing: use #1 delta delay before driving AXI-S signals post-clock-edge
  • Xilinx FFT IP with C_HAS_ARESETN=0 requires wrapper-level reset sequencing per frame
  • ROM path parameters must be verified against the actual intended ROM content (FFT-domain vs time-domain)
  • NCO enable must track s_axis_iq_tready to prevent phase/data misalignment under backpressure
