Clock domain: Single domain, aclk. No CDC crossings.

Reset dependency: aresetn must be asserted (low) then released before use. For Xilinx IP (stub=0), config channel (FWD_INV=1, SCALE_SCH=0xAA) is driven continuously with tvalid=aresetn. Protocol from parent: 1) pulse start=1; 2) stream 256 PSS samples (s_symbol_sel=0); 3) stream 256 SSS samples (s_symbol_sel=1); 4) wait for done pulse. Input samples flow with gaps (s_ready deasserts between PSS and SSS fill states).

7. Operation

Startup (S_IDLE)

On start pulse: busy=1, in_cnt=0, flush_rem=FLUSH_COUNT (=1), state=S_PSS_FILL. The four capture arrays (fft_pss_i/q, fft_sss_i/q) are not cleared on start; they are completely overwritten by the subsequent capture phases, so stale data is irrelevant.

S_PSS_FILL: Accept 256 PSS Time-Domain Samples

s_ready is high when state==S_PSS_FILL && !s_symbol_sel. Each accepted sample is packed and stored: pss_in_buf[in_cnt] <= {s_q, s_i}. After in_cnt=255: in_cnt=0, stream_cnt=0, transition to S_PSS_STREAM. SSS samples (s_symbol_sel=1) arriving during this state are ignored (s_ready=0). The extractor guarantees PSS samples arrive first.

S_PSS_STREAM: Stream PSS Buffer to FFT IP (No Gaps)

fft_s_tvalid is hardwired high whenever state is S_PSS_STREAM or S_SSS_STREAM. fft_in_data = pss_in_buf[stream_cnt]. The stream is continuous — no pipeline bubbles. fft_s_tlast asserts when stream_cnt==255. On each fft_s_ready handshake, stream_cnt increments. At stream_cnt=255: stream_cnt=0, cap_bin_cnt=0, watchdog_cnt=0. Transition: flush_rem>0 → S_PSS_FLUSH; flush_rem=0 → S_PSS_CAP.

S_PSS_FLUSH: Discard FFT Output Frame (Pipeline Drain)

Waits for 256 fft_m_valid beats (cap_bin_cnt counts 0..255). On completion: flush_rem--, stream_cnt=0, state=S_PSS_STREAM (re-stream). After re-stream, flush_rem=0, so the FSM transitions to S_PSS_CAP. The flush discards the first FFT output frame which contains residual data from the IP's internal pipeline from any previous use. Watchdog: if fft_m_valid stays low for WATCHDOG_CYCLES=2047, error=1 and state=S_DONE. This fires if aresetn was not asserted between test cases (XIP-003 root cause).

S_PSS_CAP: Capture 256 PSS FFT Bins by xk_index

On each fft_m_valid: fft_pss_i[fft_m_tuser] <= $signed(fft_m_tdata[IQ_WIDTH-1:0]) and similarly for Q. The capture address is fft_m_tuser (xk_index from IP) — not a sequential counter. This correctly places each frequency bin at its natural-order index regardless of IP output ordering. cap_bin_cnt counts to 255 for completion. Watchdog active. On completion: state=S_SSS_FILL, in_cnt=0.

S_SSS_FILL / S_SSS_STREAM / S_SSS_FLUSH / S_SSS_CAP

Mirror of PSS path with sss_in_buf and fft_sss_i/q. Since flush_rem is now 0 after PSS_FLUSH, S_SSS_STREAM transitions directly to S_SSS_CAP (no SSS flush). This reflects that the IP was already primed and stable by the PSS streaming; the SSS FFT output arrives immediately after the SSS stream without a flush frame. On S_SSS_CAP completion: stream_ptr=0, state=S_STREAM_PSS.

S_STREAM_PSS: Output PSS FFT Bins (m_symbol_sel=0)

m_valid=1, m_symbol_sel=0, m_index=stream_ptr. Data pre-fetched: m_i=fft_pss_i[stream_ptr], m_q=fft_pss_q[stream_ptr]. On m_fire: if stream_ptr<FFT_LEN-1: stream_ptr++, pre-load next bin into m_i/q/index. At stream_ptr=FFT_LEN-1: stream_ptr=0, state=S_STREAM_SSS. Pre-fetching ensures 0-cycle output stall with m_ready=1.

S_STREAM_SSS: Output SSS FFT Bins (m_symbol_sel=1)

Mirrors S_STREAM_PSS with fft_sss arrays and m_symbol_sel=1. Terminal condition: m_valid && m_ready && m_symbol_sel && stream_ptr==FFT_LEN-1. The m_symbol_sel guard prevents premature termination during the 1-cycle state transition from S_STREAM_PSS. On termination: m_valid=0, state=S_DONE.

S_DONE

Single-cycle state: m_valid=0, done=1, busy=0, state=S_IDLE. Returns immediately to S_IDLE for next invocation.

15. Known Issues and Lessons Learned

ISSUE-001 (complex_mult_iq backpressure): RESOLVED — unrelated to this module directly. Affected upstream data path.
ISSUE-002 (TB AXI-S race, #1 fix): RESOLVED — testbench timing issue. This module's ready/valid logic was correct; the TB was asserting signals on the same posedge as the DUT. Fix: add #1 delay in TB after posedge before signal assertions.
XIP-003 SSS deadlock root cause found: Xilinx FFT IP retains pipeline state from previous run. If aresetn is not asserted between test cases, the SSS fill state sees stale IP output during the SSS capture window, causing the FSM to wait indefinitely in S_SSS_CAP. Fix: (1) assert aresetn between cases in testbench; (2) FLUSH_COUNT=1 in production to absorb 1-frame pipeline latency.
XIP-003 lesson — FFT IP reset: For Xilinx xfft_v9_1 with C_HAS_ARESETN=0, the IP has no reset input. The only way to clear pipeline state is to drive a known sequence through the IP (FLUSH_COUNT=1 achieves this). The config channel (SCALE_SCH, FWD_INV) is re-driven each use but does not flush data pipeline state.
ROM parameter plumbing note: This module (fft256_dual_symbol_frontend) does not directly reference ROM files. ROM references are in meyr_integer_cfo_core. However, a related bug was found where PSS_ROM_FILE and SSS_ROM_FILE parameters were not threaded through the meyr_integer_cfo_fft_frontend_top module instantiation, causing the core to use bypass (zero) ROMs. Fixed by threading parameters explicitly. See module 07 for details.
C_THROTTLE_SCHEME=0 implication: The Xilinx FFT IP's m_axis_data_tready port is not present when C_THROTTLE_SCHEME=0. The wrapper ties fft_m_ready=1 and the IP ignores it. Consequence: data flows at full rate after each stream; downstream FSM must be in the correct CAP state when output arrives. Timing is deterministic given no backpressure on the IP input side (continuous tvalid during STREAM states).

Reset Sequence

  1. Assert aresetn=0 for ≥16 clock cycles to flush both the wrapper FSM and any IP pipeline residue.
  2. Release aresetn=1. For stub=0: verify config channel fires within 2 cycles (cfg_tvalid=1, cfg_tready asserts).
  3. Confirm state=S_IDLE (4'd0), busy=0, flush_rem=FLUSH_COUNT=1.
  4. Ensure upstream (pss_sss_symbol_extractor) is reset and idle.
  5. Pulse start=1. Verify state=S_PSS_FILL within 1 cycle, s_ready=1 (for sel=0).
  6. Between test cases: always re-assert aresetn before next start pulse to flush IP pipeline.

Hardware Risks

  • IP regeneration: If xfft_v9_1 is regenerated with different SCALE_SCH, C_ARCH, or C_THROTTLE_SCHEME, the wrapper and FSM behavior will change. Always re-run XIP-001 through XIP-004 after any IP parameter change.
  • Streaming gap detection: A gap in fft_s_tvalid during STREAM states causes the Xilinx IP to report event_tlast_missing. This sets fft_err_w=1 via the wrapper's error output, which propagates to error=1 in this module. Monitor the IP event ports via ILA.
  • Double-start without reset: Starting this module twice without reset between calls will attempt to refill pss_in_buf with new data. Since flush_rem=0 after the first PSS flush, the second PSS stream will go directly to PSS_CAP, overwriting the first PSS capture. This is correct behavior for a fresh start but may capture stale SSS data from the IP pipeline. Always reset between independent estimation calls.

17. Debug Checklist

  1. Confirm state=S_IDLE (0) and busy=0 after aresetn release.
  2. Confirm flush_rem=1 (=FLUSH_COUNT) at S_PSS_FILL entry.
  3. In S_PSS_FILL: count s_fire with sel=0; must reach 256 with no stalls if upstream is continuous.
  4. In S_PSS_STREAM: verify fft_s_tvalid=1 continuously for 256 cycles; no gaps.
  5. Verify fft_s_tlast asserts exactly at stream_cnt=255 (last PSS sample to FFT).
  6. In S_PSS_FLUSH: verify fft_m_valid pulses arrive, cap_bin_cnt reaches 255; flush_rem decrements to 0.
  7. After PSS_FLUSH: state returns to S_PSS_STREAM for 2nd stream; then transitions to S_PSS_CAP (not flush).
  8. In S_PSS_CAP: verify fft_m_tuser cycles 0..255; fft_pss_i[k] = expected FFT bin values.
  9. Verify transition to S_SSS_FILL; in_cnt resets to 0.
  10. In S_SSS_FILL: count s_fire with sel=1; must reach 256. No SSS stall (upstream extractor sends SSS after PSS tlast).
  11. In S_SSS_STREAM: verify continuous fft_s_tvalid for 256 cycles; state goes to S_SSS_CAP (not flush since flush_rem=0).
  12. In S_SSS_CAP: verify fft_m_tuser 0..255 and fft_sss_i/q[k] are correct.
  13. Verify S_STREAM_PSS output: m_valid=1, m_symbol_sel=0, m_index counts 0..255 with m_ready=1.
  14. Verify S_STREAM_SSS output: m_valid=1, m_symbol_sel=1, m_index counts 0..255.
  15. Confirm done pulse (1 cycle) at end of SSS stream; state returns to S_IDLE.
  16. If stuck in any FLUSH or CAP state: check watchdog_cnt; if approaching 2047, IP output stuck. Check aresetn sequence.
  17. If S_SSS_FILL stalls indefinitely: verify upstream extractor sends SSS samples (s_symbol_sel=1) after PSS tlast. Check pss_sss_symbol_extractor done flag.

18. Review Notes

Non-Obvious Design Decisions

  • Bin capture by tuser vs sequential counter: Using fft_m_tuser as the write address decouples the capture logic from assumptions about IP output ordering. If the IP were reconfigured for bit-reversed output, tuser would change accordingly and the capture would still be correct without any RTL change.
  • flush_rem shared across PSS and SSS paths: After FLUSH_COUNT=1 PSS flush, flush_rem=0. The SSS path reuses this counter, causing it to skip SSS flush. This is intentional design: after the PSS FFT streaming, the IP is warmed up and the SSS output is clean. Resetting flush_rem at S_SSS_STREAM would force an unnecessary SSS flush, adding ~512 cycles to the total latency.
  • Pre-fetch in S_STREAM_PSS/SSS: The RTL loads the next bin's data into m_i/q/index on the same clock as m_fire. This is only valid because the capture buffers are write-complete by the time any STREAM state is entered. No write-read conflict is possible.
  • m_symbol_sel guard in S_STREAM_SSS: The condition m_valid && m_ready && m_symbol_sel prevents the SSS stream from terminating on the first clock after S_STREAM_PSS exits, before m_symbol_sel has been updated to 1. This is a 1-cycle pipeline protection against registered m_symbol_sel lag.
  • WATCHDOG_CYCLES=2047 is empirically safe: The Xilinx xfft_v9_1 256-pt streaming FFT produces output within ~300 cycles of the last input. WATCHDOG_CYCLES=2047 provides 6.8× margin. If a faster clock is used, this margin must be recalculated.

Notes for Future Engineers

  • USE_BEHAVIORAL_STUB=3 is simulation-only and excluded from synthesis via the generate block. Never set USE_BEHAVIORAL_STUB=3 in the synthesis constraint file or Vivado project settings.
  • The 12-state FSM encodes states as 4-bit values. Adding more states (e.g., a 4th symbol) fits in the 4-bit encoding up to 15 states. The default case returns to S_IDLE safely.
  • If FLUSH_COUNT needs to be 0 for a different IP variant, the flush loop is skipped entirely (flush_rem=0 on entry to S_PSS_STREAM causes immediate transition to S_PSS_CAP). Verify with the specific IP's pipeline latency specification before setting FLUSH_COUNT=0.
