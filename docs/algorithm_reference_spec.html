1. Project Purpose

The C reference code (ref/receiver.c, ref/signal_processing_common.c) is the golden algorithm model for this OFDM/NR-style frame synchronizer. It operates on floating-point IQ arrays with direct random access.

The RTL design (rtl/phase3_sync_top.v and its hierarchy) is a fixed-point streaming hardware implementation of the same algorithm, targeting FPGA deployment via AXI-Stream. Samples traverse the pipeline in strict order — no random access is possible without a replay buffer.

ArithmeticIEEE-754 single-precision floatFixed-point signed 16-bit I/Q; Q1.15 for phase; 32/40/48-bit accumulators
Memory accessRandom-access float arraysAXI-S streaming; replay buffer required for re-processing
FFT engineFFTW3 fftwf_execute_dft()Xilinx FFT IP (fft256_xilinx_wrapper.v); behavioral DFT stub in simulation

Key system parameters: NSC=256 · CP_LEN=32 · FRAME_LEN=576=2×(NSC+CP_LEN) · PSS_OFFSET=32 · SSS_OFFSET=320 · NUM_SYN_BLOCKS=2 · FFT_SIZE=256

2. End-to-End Synchronization Flow

In the C reference, stages run as sequential calls inside synchronization() (receiver.c:261). In the RTL, Stages 0–3 are pipelined inside frac_cfo_frame_corrector_top.v; Stages 4–6 drive the Meyr FFT frontend; Stages 7–8 are handled by the DMA wrapper with the IQ replay buffer.

5. Mathematical Formulation

5.1 Frame Detection — Energy Envelope

Sliding window average energy at position j:

E(j) = (1/W) × Σi=jj+W−1 (I[i]² + Q[i]²)     W = 25

Frame start criterion (10-consecutive-hit rule):

frameStart = min { j : E(j+k) > θ for all k = 0..9 }     θ = 40000 (float) = 10,240,000 × Q1.15 scale
RTL note: The RTL pre-multiplies threshold by window_len to avoid division: thresh_mult = threshold_in × window_len_in. Case 1 and Case 2 are both implemented in frame_detect_fsm.v.

5.2 CP Autocorrelation

For symbol boundary lag d (d = 0..255):

P(d) = Σi=031 r[i+d] × conj(r[i+d+N])    N=256, CP_LEN=32

In real arithmetic (C reference):

Re(P(d)) = Σ [ I[i+d]·I[i+d+N] + Q[i+d]·Q[i+d+N] ]
Im(P(d)) = Σ [ −I[i+d]·Q[i+d+N] + Q[i+d]·I[i+d+N] ]

Energy normalization:

R(d) = Σi=031 (|r[i+d+N]|² + |r[i+d]|²)

5.3 Van de Beek Timing Metric

M(d) = 2 × |P(d)| − R(d)     d_peak = argmaxd=0..255 M(d)

At perfect timing, |P(d_peak)| ≈ R(d_peak)/2, so M(d_peak) ≈ 0. The argmax finds the OFDM symbol boundary in the received stream.

5.4 Fractional CFO Estimation

ε_frac = −∠P(d_peak) / (2π) = −atan2(Im(P(d_peak)), Re(P(d_peak))) / (2π)

Units: normalized frequency (subcarrier bins). Range: (−0.5, +0.5).

RTL encoding: frac_phase is Q1.15 signed 16-bit. frac_phase = 0x7FFF corresponds to +π radians. CORDIC latency: 15 pipeline stages + 2 FSM overhead = 17 cycles.

5.5 CFO Correction (Fractional and Integer)

y[n] = x[n] × exp(−j × 2π × ε × n / NSC)     ε = ε_frac (Stage 3) or ε = k_int (Stage 7)

RTL NCO implementation:

phase[n] = (phase[n−1] + step) mod 2³²
rotI[n] = cos(2π × phase[n] / 2³²)     rotQ[n] = sin(2π × phase[n] / 2³²)
y_I[n] = x_I[n]·rotI[n] − x_Q[n]·rotQ[n]
y_Q[n] = x_Q[n]·rotI[n] + x_I[n]·rotQ[n]

Integer CFO step word:

step = −k_int × 232 − log₂(NSC) = −k_int × 2²⁴    (NSC=256)

5.6 PSS/SSS Extraction Boundaries

From slotStartIndex (= frameStart + d_peak) in C reference:

PSS: rxI[slotStart+CP_LEN .. slotStart+CP_LEN+NSC−1] = [slotStart+32 .. slotStart+287]
SSS: rxI[slotStart+2·CP_LEN+NSC .. slotStart+FRAME_LEN−1] = [slotStart+320 .. slotStart+575]

RTL extractor counts from frac-corrected stream output sample 0 (stream begins at detected slot start):

PSS window: corrected output samples [32 .. 287]   (PSS_OFFSET = CP_LEN = 32)
SSS window: corrected output samples [320 .. 575]   (SSS_OFFSET = 2·CP_LEN+NSC = 320)

5.7 Meyr Integer CFO Estimation

Received cross-product (term1):

ĜPSS[k] = DFT{PSS_time}[k]   ĜSSS[k] = DFT{SSS_time}[k]   (256-pt, natural order)
term1[k] = ĜPSS[k] × conj(ĜSSS[k])

Reference cross-product (term2):

term2[k] = mU[k+CP_LEN] × conj(goldU[k+CP_LEN])    k=0..255

Cross-correlation and peak decode:

corr[p] = Σk term1[k] × conj(term2[k−p])    (linear via zero-pad FFT in C reference)

p_peak = argmaxp |corr[p]|²
k_int = p_peak − (NSC−1) = p_peak − 255    range: [−255, +255] bins

9. Known Open Functional Risks

ISSUE-001 (CRITICAL) — complex_mult_iq.v: Backpressure Ignored

Location: rtl/complex_mult_iq.v, lines 44–45

    assign s_axis_a_tready = 1'b1;   // line 44 — HARDWIRED — BUG
    assign s_axis_b_tready = 1'b1;   // line 45 — HARDWIRED — BUG

Root cause: Output register updates unconditionally every cycle. Any downstream m_axis_tready=0 stall causes data to be overwritten before it is consumed.

SSS deadlock sequence:

  1. s_axis_a_tready=1 always → upstream blasts all 576 frac-corrected samples in ~1152 cycles.
  2. PSS/SSS extractor enters SSS_FILL at sample 320 and asserts frac_m_tready=0 while holding PSS.
  3. But the corrector does not stall — samples 321–575 (SSS) are silently dropped.
  4. SSS_FILL receives sample 320 (in_cnt=0) then s_valid=0 permanently → deadlock.
  5. P3-16A INTEGRATION_GATE: FAIL.

Planned fix (NOT YET APPLIED):

    assign s_axis_a_tready = !m_axis_tvalid || m_axis_tready;
    assign s_axis_b_tready = s_axis_a_tready;
    // Gate output register:
    always @(posedge aclk) begin
        if (m_axis_tready || !m_axis_tvalid) begin
            m_axis_tvalid <= s_axis_a_tvalid && s_axis_b_tvalid;
            m_axis_tdata  <= { out_Q_shifted[...], out_I_shifted[...] };
        end
    end
    // Also gate NCO phase advance in nco_phase_gen.v

Algorithm mismatch: C reference accesses rxI[slotStart+320..575] directly. RTL must stream SSS in order — dropped samples cannot be recovered.

ISSUE-002 (MEDIUM) — P3-15D Random Equivalence: 15% Metadata Failures

Observed: session_D4_p3_15d: 85/100 PASS, 15 failures in d2_slot_start and/or d2_frac_cfo fields. D3 IQ body comparison always PASS (max_err=0).

Example: case_015 — pre_zeros=60, eps_frac=−0.0724, k_int=0, snr=42.7dB.

Hypotheses:

  • A — Timing boundary: Near-equal M(d) at two lags. Float C reference and fixed-point RTL argmax resolve tie differently by ±1 sample.
  • B — CORDIC quantization: CORDIC ±1 LSB in Q1.15 phase word pushes frac_cfo comparison outside tolerance window at boundary epsilon values.
  • C — Comparison tolerance: Script uses exact equality; 1-LSB discrepancy in Q1.15 causes comparison failure even though RTL data output is correct.

Status: Root cause NOT YET DETERMINED. NOT YET FIXED. Diagnose by diffing failing case_NNN_meta.json D2 fields.
