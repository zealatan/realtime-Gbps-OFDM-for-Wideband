# Phase 3 — Golden Dump Format Specification

**Version:** 1.0  
**Date:** 2026-05-27

---

## Overview

The golden dump is a text file produced by `scripts/golden_dump.c` (compiled to
`scripts/golden_dump`). It captures internal C reference synchronization values at
defined checkpoints so that the RTL simulation can compare against them.

All files are written to the `golden/` directory created under the project root.

---

## File: `golden/phase3_golden_values.txt`

Primary comparison file. One record per line, format:

```
KEY <value>
```

Keys are case-sensitive. Lines beginning with `#` are comments. Values are printed with
enough precision to avoid rounding loss (use `%.9g` for floats).

### Required Keys

| Key | C Source | Type | Example |
|---|---|---|---|
| `FRAME_START` | frame_detector() return | int | `FRAME_START 42` |
| `PEAK_INDEX_AUTO` | VanDeBeekAutoCorrelation() return | int | `PEAK_INDEX_AUTO 187` |
| `SLOT_START_INDEX` | peakIndexAuto + frameStart | int | `SLOT_START_INDEX 229` |
| `AUTOCORR_I_AT_PEAK` | autoCorrOutI[peakIndexAuto] | float | `AUTOCORR_I_AT_PEAK 1.23456789e+04` |
| `AUTOCORR_Q_AT_PEAK` | autoCorrOutQ[peakIndexAuto] | float | `AUTOCORR_Q_AT_PEAK -3.45678901e+02` |
| `ENERGY_AT_PEAK` | normalizedValue_1[peakIndexAuto] from auto_corr | float | `ENERGY_AT_PEAK 2.10000000e+04` |
| `METRIC_AT_PEAK` | normalizedValue_2[peakIndexAuto] | float | `METRIC_AT_PEAK 5.67890123e+03` |
| `FRAC_CFO_OFFSET` | fracfreqOffset = −atan2(Q,I)/(2π) | float | `FRAC_CFO_OFFSET -1.23456789e-03` |
| `DETECTION_STATUS` | 0=fail, 1=success | int | `DETECTION_STATUS 1` |

### Example File

```
# Phase 3 Golden Reference Values
# Generated by: scripts/golden_dump  tb/data/iq_stimulus.f32
# Date: 2026-05-27
# NSC=256 CP_LEN=32 frameStart forced to 0

FRAME_START 0
PEAK_INDEX_AUTO 187
SLOT_START_INDEX 187
AUTOCORR_I_AT_PEAK 1.234567890e+04
AUTOCORR_Q_AT_PEAK -3.456789010e+02
ENERGY_AT_PEAK 2.100000000e+04
METRIC_AT_PEAK 5.678901230e+03
FRAC_CFO_OFFSET -1.234567890e-03
DETECTION_STATUS 1
```

## File: `golden/phase3_autocorr_full.txt`

Full autocorrelation trace for all NSC=256 lags. Used for per-sample metric comparison.
One line per lag:

```
# lag  P_I  P_Q  energy  metric
0  0.000000000e+00  0.000000000e+00  0.000000000e+00  0.000000000e+00
1  1.234567890e+02  -5.678901230e+01  9.000000000e+02  -6.554321780e+02
...
255  ...
```

Format: space-separated, `lag P_I P_Q energy metric`, `%.9g` precision.

---

## File: `golden/phase3_iq_stimulus.f32`

Binary float32 input IQ file fed to both golden_dump and RTL testbench.
- Format: interleaved float32, alternating I then Q: `I0 Q0 I1 Q1 ...`
- Little-endian
- Total samples: `total_rx_frame_len = (symbols_per_slot + burst_len) * 2` float values

This file is the ground truth input. Both C and RTL must use identical samples.

---

## File: `golden/phase3_iq_stimulus_q15.hex`

16-bit signed fixed-point version of the IQ stimulus for RTL testbench injection.
- Conversion: `int16_t sample = (int16_t)(float_val * 32768.0f)` with saturation
- Format: one 32-bit hex word per line (upper 16 bits = Q, lower 16 bits = I)
  matching RTL s_data[31:16]=Q, s_data[15:0]=I convention
- Example line: `FFFF0123`  (Q=0xFFFF=−1, I=0x0123=+291)

---

## File: `sim_out/rtl_results.txt`

Produced by the RTL testbench (`tb/phase3_sync_reference_compare_tb.sv`).
Same key=value format as the golden file.

| Key | Source in RTL | Type |
|---|---|---|
| `RTL_LOCK_INDEX` | lock_index at timing_lock | int |
| `RTL_PEAK_P_I` | peak_p_i at timing_lock | signed 48-bit (decimal) |
| `RTL_PEAK_P_Q` | peak_p_q at timing_lock | signed 48-bit (decimal) |
| `RTL_METRIC_AT_LOCK` | metric_dbg at timing_lock | uint32 (decimal) |
| `RTL_FRAC_PHASE` | frac_phase_dbg after est_frac_valid | int16 (decimal, Q1.15) |
| `RTL_NCO_LOCKED` | nco_locked | 0 or 1 |

## Conversion Rules for Comparison

### Fixed-point → float

```
C_float  = RTL_int48  / (float)(1 << SCALE_SHIFT)
```

The scale shift depends on the fixed-point range of the input. With 16-bit IQ (Q1.15 scaled
to ±32767) and CP_LEN=32:
```
peak_p_i max ≈ 32767² × 32 = 3.4 × 10¹⁰  (fits in 48 bits)
```
There is no fixed-point scale normalization in the RTL accumulators; raw integer accumulation
is used. The comparison script must scale C floats to the same integer range:
```
C_float_as_fixed = C_autocorr_I * (2^15)^2 * CP_LEN
                 = C_autocorr_I * 32768^2 * 32
```
Then compare directly with `RTL_PEAK_P_I` (integer).

### Q1.15 Phase Conversion

```
RTL frac_phase (Q1.15):  range [−32768, +32767] maps to [−π, +π)
C fracfreqOffset:         range [−0.5, +0.5] (cycles/sample normalized)

Relationship:
  RTL_phase = atan2(P_Q, P_I)                  [radians, via CORDIC]
  C_offset  = −atan2(P_Q, P_I) / (2π)

Conversion:
  RTL_phase_float = frac_phase * π / 32768.0   [radians]
  C_atan2_value   = −C_fracfreqOffset * 2π     [radians]
  
  Compare: RTL_phase_float ≈ C_atan2_value
           (sign difference because C negates before applying)
```

## Comparison Script Interface

`scripts/compare_golden_rtl.py golden/phase3_golden_values.txt sim_out/rtl_results.txt`

Exits 0 on PASS, non-zero on FAIL. Prints a table of all comparisons with status.
