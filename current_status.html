HW ZCU216 DMA-Free Digital-Loopback Bring-Up working · 2026-06-23

DMA-free digital-loopback port of the OFDM sync DUT: BRAM stim player → packaged DUT IP → BRAM capture. Control & readback via indexed GPIO + AXI-Lite (no DMA). Board ZCU216 RFSoC (xczu49dr-ffvf1760-2-e), branch RX_SYNC, tools Vivado 2021.1 + Vitis 2022.2. Committed locally as e530863 (push pending).

  • AXI-Lite control pathworking Root cause: a reused psu_init set PS HPM0 to 128-bit on a 32-bit BD, breaking all PL register accesses at offset ≠ 0. Fixed by using the build's own 32-bit-HPM0 psu_init.
  • Bypass digital loopbackbit-exact 4160 / 4160 Player → DUT passthrough → capture matches exactly.
  • Normal-mode OFDM sync (vector tc0000)golden-exact Frame detection fsv=1, frame_start_index=41, peak_index=23, slot_start=64 — exactly match the C / Python golden. m_axis output is magnitude-preserved (data integrity good).
  • Required HW fixesapplied Baked bk_conj_fft512_rom.txt (FFT-correlation B[k]* ROM) into the DUT IP (else all-zero ROM → PSS correlation never fires); overrode frame-detector THRESHOLD 10240000 → 40000 (default was 256× too high → no detection).
  • Integer-CFO path (B[k]-matched CFO sweep)tracks · +60 offset GPIO-load sweep of k_int = 0, ±4, ±8 → decoded index = 60 + k_int exactly (slope 1, perfect tracking). The integer-CFO decode works on hardware — it is not broken, only carries a constant +60-bin offset (persistent, not cold-start; the meyr core is 0-offset in sim, so the offset is introduced by the on-board PSS-extraction alignment). Remaining: calibrate / localize the +60.
  • Clock / throughput (200 MHz target)timing MET Rebuilt with debug ILA removed; PS PLL granularity delivers 187.5 MHz (WNS +0.622 ns, Fmax ~212 MHz). AXI-S is 32-bit = 1 sample/clock → 187.5 Msps (up from the 100 MHz bring-up clock). Sustained normal-mode duty is meyr-serialized (ISS-24).
  • Detection robustness regression (8 diverse vectors)7/8 board=sim Board detection (frame_start / peak / slot) matches the iverilog Stage-1 sim golden across scale ×0.25, AWGN 10 dB, multipath, and frame-positions 64/96. The lone miss, frame-position 48 (minimal pre-padding), is a one-shot startup lead-in artifact — being fixed with a player LEAD_IN=64 warmup (rebuild in progress → expected 8/8). Not a detection-algorithm flaw (sim detects it correctly).

Overall: the ported DUT detects / aligns / CFO-corrects / streams on hardware, and C-reference → RTL → hardware traceability is established.
