Clock Domain

Single clock domain: clk (note: uses clk, not aclk, as the port name). All logic is synchronous to this clock. Reset is active-low asynchronous: aresetn.

Upstream Boundary Signals

Write side: wr_valid / wr_ready / wr_data[31:0]. Source is the AXI-S output of the frac CFO corrector output FIFO or passthrough path in the wrapper. wr_ready is deasserted outside S_CAPTURING to apply back-pressure.

Downstream Boundary Signals

Read side: rd_valid / rd_ready / rd_data[31:0] / rd_tlast. Drives the integer NCO correction chain (nco_phase_gen + complex_rotator) inside phase3_sync_axis_dma_wrapper. The wrapper fires replay_start after integer NCO warmup: int_nco_wu_cnt == 1.

Reset Sequence

On aresetn=0: state → S_CAPTURING, all counters/pointers to 0, all output registers cleared. The clear synchronous input provides an in-band restart without asserting the full reset pin: it returns to S_CAPTURING and resets wr_ptr, rd_ptr, s1_pending, capture_error, and replay_busy, but does NOT erase BRAM contents.

BRAM Attribute

(* ram_style = "block" *) forces Xilinx synthesis to map the mem array to a block RAM primitive (BRAM18E2 on Artix-7/Zynq). Without this attribute, synthesis might choose distributed RAM (LUTRAMs), which would consume hundreds of LUTs. With DATA_W=32 and 1024 entries: 32Kb total allocated, but only 576×32b = 18.4Kb is used. The BRAM18E2 capacity is exactly 18Kb (18,432 bits). The allocated array (32Kb) technically exceeds this and may map to 2 BRAM18E2s in Vivado (or use a BRAM36); verify in implementation utilization report. The design is functionally correct with either 1 or 2 BRAMs.

7. Operation — Detailed Engineering Description

Startup

After aresetn deasserts (or after clear), the module enters S_CAPTURING. wr_ready goes high immediately (combinatorial from state). The write pointer wr_ptr is 0. The module is ready to accept IQ samples.

S_CAPTURING — Write / Capture Phase

Every clock where wr_valid & wr_ready (wr_fire): the sample wr_data is written to mem[wr_ptr]. wr_ptr increments. When wr_ptr == FRAME_LEN-1 (the 576th sample, index 575): capture_done is asserted for exactly 1 cycle; wr_ptr resets to 0; state transitions to S_CAPTURED.

Side effect: if replay_start is received while in S_CAPTURING, capture_error is set (sticky). This indicates the calling logic made a sequencing error. The capture continues normally; the error flag persists until cleared.

S_CAPTURED — Idle (Buffer Full)

wr_ready is now 0 (not in S_CAPTURING), preventing any further writes. The BRAM holds the complete captured frame. The module waits for a replay_start 1-cycle pulse. On replay_start: rd_ptr resets to 0; s1_pending and s1_last clear; replay_busy sets; state → S_REPLAYING.

S_REPLAYING — 2-Stage BRAM Read Pipeline

The read pipeline consists of two pipeline stages to handle the 1-cycle BRAM read latency:

  • Stage 1 (s1): do_read fires when: state=S_REPLAYING AND s1_pending=0 AND s2_can_accept AND rd_ptr < FRAME_LEN. When do_read fires: the BRAM read of mem[rd_ptr] is issued (mem_q will have the result next clock); s1_pending is set to 1; s1_last records whether this is the last sample (rd_ptr == FRAME_LEN-1); rd_ptr increments.
  • Stage 2 (s2 — output hold register): When s1_pending=1 (i.e., a BRAM result is incoming in mem_q this cycle), the output hold register loads: rd_data <= mem_q; rd_tlast <= s1_last; rd_valid <= 1. When rd_valid & rd_ready (sample consumed) with no incoming s1 result: rd_valid <= 0.
  • Backpressure: s2_can_accept = !rd_valid | (rd_valid & rd_ready). If downstream stalls (rd_ready=0 while rd_valid=1), s2_can_accept=0, which also prevents do_read from firing. The pipeline stalls cleanly.
  • Throughput: In the unthrottled case, one do_read fires every 2 cycles (1 cycle for S1, 1 cycle to load S2). Replaying 576 samples takes 576×2 = 1152 clock cycles minimum.

Transition to S_DONE occurs when: rd_valid & rd_ready & rd_tlast — i.e., the last sample is consumed by the downstream. This also asserts replay_done and clears replay_busy.

S_DONE — Terminal State

The module remains in S_DONE after a replay completes. The BRAM contents are preserved. A subsequent replay_start pulse (which would require returning to S_CAPTURED first via clear) can re-trigger replay. To capture a new frame, clear must be asserted, returning to S_CAPTURING.

clear Signal Behavior

Synchronous clear has highest priority over all FSM state transitions (checked before the case statement in the main always block). When asserted: state → S_CAPTURING; wr_ptr ← 0; rd_ptr ← 0; s1_pending ← 0; s1_last ← 0; capture_error ← 0; replay_busy ← 0. The rd_valid/rd_data/rd_tlast output stage is independently cleared by a separate always block watching clear. The BRAM memory array contents are NOT affected by clear.

Corner Cases

  • Replay during capture: capture_error set; capture continues uninterrupted.
  • Multiple replay_start pulses in S_CAPTURED: Only the first is acted upon (state moves to S_REPLAYING; subsequent pulses in S_REPLAYING are ignored by the case statement).
  • rd_ready deasserted after last sample issued: rd_tlast is held stable in the output hold register until consumed. No data loss.
  • clear during S_REPLAYING: Aborts replay cleanly. Output registers are cleared. rd_valid drops to 0 immediately.
  • do_read at rd_ptr=FRAME_LEN-1: s1_last is set, rd_ptr increments to FRAME_LEN (not harmful since do_read only fires when rd_ptr < FRAME_LEN; this check prevents an extra spurious read).

10. Algorithm Mapping

No direct C-reference — hardware realization of re-reading rxI/rxQ[slot_start + n] that the C reference does with plain array indexing. In receiver.c the "replay" is not a function: the captured receive arrays rxI/rxQ are simply re-addressed by slotStartIndex + n each time a correction pass re-reads the slot. The buffer performs the identical re-read in silicon, sourcing the same sample stream from a captured BRAM copy instead of from a re-indexed array in host memory.

The replay buffer is an infrastructure module, not a direct algorithm implementation. It enables the two-pass correction architecture:

rd_addr = n,   n = 0…FRAME_LEN−1   ≡   rxI[slot_start + n],  rxQ[slot_start + n]

Buffer base address 0 corresponds to the C pointer offset slotStartIndex; the read pointer n supplies the running index that the C reader adds to slot_start.

// Illustrative HW sequence (only synchronization()/apply_carrier_freq_offset() are real C fns in ref/receiver.c) // Pass 1: capture raw IQ frame, run sync algorithm raw_frame = capture_iq_frame(576_samples); // HW action → S_CAPTURING → S_CAPTURED synchronization(raw_frame, &frac_cfo, &int_cfo); // real C fn @ receiver.c:261 (Phase3 sync top) // Pass 2: replay with integer CFO correction load_integer_nco_step(int_cfo); // HW action: NCO step word loaded warmup_nco(CORDIC_LATENCY + 1); // HW action: 16 cycles warmup replay_start(); // HW action: → S_REPLAYING (re-read of buffer) corrected_frame = apply_carrier_freq_offset(raw_frame, int_cfo); // real C fn @ receiver.c:443 → complex_rotator

Without the replay buffer, the raw IQ frame would need to be re-streamed from the PS/DMA, requiring a second DMA transaction and losing the real-time processing window. The replay buffer enables a single-pass receive with post-processing correction.

The C reference function apply_carrier_freq_offset() (@ receiver.c:443) is implemented in hardware by the NCO (nco_phase_gen) + rotator (complex_rotator) chain downstream of this buffer in the DMA wrapper; its inner rotation on sample j is out[j] = in[j]·e j2πf(j+startPoint)/fs. This buffer's sole job is to re-supply in[j] from the captured slot.

15. Known Issues & Lessons Learned

All verification gates PASS as of 2026-06-04. No open issues on this module.

Resolved: No Issues on iq_replay_buffer_576

ISSUE-001 (complex_mult_iq backpressure) and ISSUE-002 (TB AXI-S race) are in downstream modules and are both RESOLVED. They do not affect this module directly.

Lessons Learned

  • Throughput half-rate: The 2-stage BRAM read pipeline gives 1 sample per 2 cycles, not 1 per cycle. Early integration assumed full rate; the wrapper NCO warmup counter and TLAST counter were adjusted accordingly.
  • clear does not erase BRAM: BRAM content persists through clear. Stale data from a previous capture is not visible to a new capture (new data overwrites from address 0) but may be read if rd_ptr is driven past wr_ptr in an incomplete capture scenario. Always complete capture before replay.
  • S_DONE requires clear to exit: Unlike some buffer designs that auto-return to S_CAPTURED after replay, this module stays in S_DONE. The wrapper must issue clear (via soft_reset_pulse) to start a new frame. This is intentional — prevents accidental re-capture.
  • ram_style attribute: Without (* ram_style = "block" *), Vivado may infer distributed RAM consuming 576 LUTs. Always verify the utilization report shows BRAM primitive usage.
  • Clock name mismatch: This module uses clk not aclk. All connecting logic in the wrapper must bind to the same clock net. This was verified in P3-14B.

Expected Bring-Up Sequence

  1. Assert aresetn=0 for ≥4 cycles; deassert. Module enters S_CAPTURING.
  2. Write 0x01 to AXI register 0x04 (CONTROL: enable=1). DMA stream begins flowing.
  3. Observe capture_done pulse after exactly 576 wr_fire events on ILA.
  4. Observe state transition to 2'd1 (S_CAPTURED).
  5. Phase3 sync algorithm runs (~35,000+ cycles).
  6. DMA wrapper loads integer NCO step word; starts NCO; waits 16 cycles warmup.
  7. Wrapper asserts replay_start for 1 cycle (int_nco_wu_cnt==1).
  8. Observe replay_busy=1 on ILA; monitor rd_valid stream beginning.
  9. After 1152+ clocks, observe rd_tlast pulse and then replay_done.
  10. Downstream DMA receives 576 integer-CFO-corrected samples.

Hardware Risks

  • BRAM utilization: Check Vivado implementation report for RAMB18E2 vs RAMB36E2 usage. If 2 BRAM18E2s are instantiated, verify timing closure at target frequency.
  • rd_ready tie-off: If the downstream pipeline (integer NCO + rotator) is not ready before replay_start, the first few samples may be lost (rd_valid=1 but rd_ready=0 on cycle 2 of replay). The wrapper NCO warmup should guarantee readiness.
  • clear timing: Do not assert clear during the S_REPLAYING to S_DONE transition to avoid losing the replay_done pulse which signals the DMA wrapper.

17. Debug Checklist

  1. capture_done never fires: Check wr_valid is being driven. Check wr_ready is high (state=S_CAPTURING). Count wr_fire events — should reach 576.
  2. capture_error is set: replay_start was driven before capture_done. Review wrapper sequencing; ensure replay_start is gated by capture_done.
  3. replay_start ignored: Verify state=2'd1 (S_CAPTURED) when replay_start fires. State must not be S_CAPTURING, S_REPLAYING, or S_DONE.
  4. rd_valid never asserts after replay_start: Check do_read fires — requires state=S_REPLAYING, s1_pending=0, s2_can_accept=1, rd_ptr<576. Check rd_ready is not stuck low before first sample.
  5. replay throughput too slow: Check rd_ready pattern. Count clock cycles between rd_valid assertions; should be 2 when rd_ready=1 constantly.
  6. rd_tlast on wrong sample: FRAME_LEN parameter mismatch. Verify FRAME_LEN=576 at instantiation. Count rd_valid pulses before rd_tlast.
  7. replay_done never fires: rd_tlast may be asserted but rd_ready not asserted to consume the last sample. Check downstream consumer.
  8. BRAM inferred as LUTRAMs in synthesis: Confirm (* ram_style = "block" *) attribute is present. Check synthesis log for “BRAM18E2” vs “RAM32M” references.
  9. State stuck in S_DONE: Normal — requires clear pulse (via soft_reset from AXI register) to return to S_CAPTURING for next frame.
  10. Data corruption after clear: Verify clear is not asserted during an active BRAM write (wr_fire). Clear deasserts wr_ptr but the in-progress write completes; next capture starts from address 0 and overwrites cleanly.

18. Review Notes & Non-Obvious Design Decisions

Why 2-Stage Pipeline?

The BRAM18E2 has 1 clock cycle of read latency (registered output mode, required for synthesis inference). A naive single-cycle read would not work — the data is not available combinatorially. The 2-stage pipeline (S1: issue address; S2: capture result into output hold register) is the minimal correct implementation.

s2_can_accept and do_read Gate

The condition do_read = (state==S_REPLAYING) & !s1_pending & s2_can_accept & (rd_ptr<FRAME_LEN) is carefully constructed: it prevents issuing a new BRAM read when the S2 output register cannot accept a new result. This ensures no BRAM data is ever lost or overwritten. The invariant “when s1_pending=1, rd_valid is guaranteed 0” (from the header comment) is maintained by this gate.

wr_ready is Combinatorial

assign wr_ready = (state == S_CAPTURING) is combinatorial from the state register. This is safe — the state register is stable between clock edges. The combinatorial wr_ready may glitch during state transitions at the rising clock edge if the downstream does not honor setup/hold, but standard AXI-S practice accounts for this (downstream samples on posedge).

capture_done and replay_done as Pulses

Both control outputs default to 0 every cycle (capture_done <= 1'b0; replay_done <= 1'b0; at the top of the always block). They are only set to 1 in the specific cycle they fire. This is intentional — callers must latch these pulses themselves or use them as direct trigger events.

FRAME_LEN Assertion

The $fatal checks (synthesis translate_off) catch configuration errors at simulation time: FRAME_LEN exceeding BRAM address space or FRAME_LEN=0. These are compile-time assertions that prevent silent data truncation bugs when parameters are changed.

Clock Name Convention

This module uses clk as its clock port name, unlike most other modules in the project which use aclk. Future engineers: this is not a bug but a naming convention leftover from the P3-10A standalone development. The DMA wrapper correctly maps the system clock to this clk port.

BRAM Size vs FRAME_LEN

The BRAM is allocated 1024 entries (ADDR_W=10) but only 576 are used. The 448 unused entries waste BRAM capacity but are harmless. Reducing ADDR_W to $clog2(FRAME_LEN) = 10 (since 2^10=1024≥576) would not change resource usage. Reducing to 9 (2^9=512 < 576) would fail the compile-time assertion.

Future Work

The register comment at 0x44 (INT_CFO_APPLIED) notes “TODO: replay buffer not yet connected.” This sticky bit should be wired to replay_busy rising edge from this module. As of 2026-06-04, this TODO remains open in phase3_axi_lite_regs.v but does not affect functional correctness.
