The wrapper's gated s_axis feed arrives at this module. phase3_sync_top implements the full C-reference synchronization() function as an RTL orchestration layer. It instantiates four sub-modules that run concurrently after a single start pulse, and waits for either the Meyr algorithm to complete (success path) or the frame detector to fail (error path).

Clock Domain and Reset

Single clock domain: aclk. Reset input is aresetn (this module's aresetn is already the post-soft-reset version from the wrapper: dut_aresetn = aresetn && !soft_reset_r). The FSM uses asynchronous reset (negedge aresetn) for reliable simulation behavior. Error recovery requires full aresetn toggle — no partial-reset mechanism exists inside this module.

7 Operation

Reset

FSM uses negedge aresetn for asynchronous clear. On reset: state=S_IDLE, done/busy/error=0, error_code=0, frac/ext/meyr start regs=0, int_cfo_step_word_r=0, int_cfo_valid_r=0. All sub-modules receive the same aresetn signal.

S_IDLE — Waiting for Start

FSM waits with busy=0. On start && !busy: set busy=1, pulse frac_start_r=1, ext_start_r=1, meyr_start_r=1 all simultaneously in the same clock cycle, clear error/error_code. Transition to S_RUN.

The simultaneous start of all three sub-modules is a deliberate design choice. The extractor and Meyr modules enter their wait states immediately and block on data that only becomes available thousands of cycles later (when the frac corrector finishes). This avoids a sequential start-confirmation handshake without risking first-sample loss.

S_RUN — Concurrent Algorithm Execution

Sub-module execution ordering driven by data dependencies:

  1. u_frac_corr: fills iq_frame_buffer (576 samples minimum), runs frame_detector (sliding window scan), runs CP autocorrelation (VanDeBeek), estimates frac CFO via CORDIC atan2, then streams FRAME_LEN=576 frac-corrected samples on frac_m_*. Total: thousands of clock cycles.
  2. u_ssc: triggers on u_frac_corr's frac_done. Computes slot_start = frame_index + peak_lag and provides constant PSS/SSS window offsets (pss_fft_start=CP_LEN=32, sss_fft_start=2*CP_LEN+NSC=320) as wires to u_extractor.
  3. u_extractor: started with ext_start_r; enters streaming mode and waits for frac_m_tvalid. Counts through 576 samples on the frac_m_* bus. Extracts PSS window (samples 32..287 = NSC samples) and SSS window (samples 320..575 = NSC samples) and emits them sequentially to u_meyr_fft (symbol_sel=0 then 1).
  4. u_meyr_fft: started with meyr_start_r; waits for PSS then SSS symbol data from u_extractor. Applies dual-symbol FFT256, cross-correlates PSS_FFT · SSS_FFT against synthetic Meyr reference, finds cross-correlation peak position = integer CFO in bins. Asserts meyr_done when complete.

S_RUN Terminal Conditions

  • frac_frame_error (priority): frame_detector did not find a valid frame (or INPUT_ACQ_TIMEOUT watchdog). FSM sets error=1, error_code=frac_error_code, transitions to S_DONE. int_cfo_step_word is NOT latched. Extractor and Meyr remain in partially-completed states; full reset required before next run.
  • meyr_done: Meyr algorithm completed successfully. FSM latches int_cfo_step_word_r = (-int_cfo_ext) << INT_CFO_SHIFT, asserts int_cfo_valid_r=1 for 1 cycle, transitions to S_DONE.

Integer CFO Step Word Computation

meyr_int_cfo is a signed 16-bit integer: estimated frequency offset in FFT bin units. The NCO step word is computed combinatorially:

  • int_cfo_ext = sign_extend_32(meyr_int_cfo)
  • int_cfo_step_word = (-int_cfo_ext) << INT_CFO_SHIFT

The negation cancels the measured offset (positive CFO = NCO rotates negatively). The left shift by 24 scales from bins to 32-bit phase-accumulator increment per sample: 1 bin = fsamp/NSC Hz = (1/NSC) · fsamp; NCO step for f Hz = (f/fsamp) · 232. Combining:

step = (1/NSC) · 232 = 2(32−log₂NSC) = 224  per bin

S_DONE — Completion

Asserts done=1, clears busy=0, transitions unconditionally to S_IDLE in the same clock cycle. The done pulse is registered and exactly 1 cycle wide. The wrapper start-arm logic detects this to trigger NCO warmup and replay.

15 Known Issues / Lessons Learned

ISSUE-001 RESOLVED (P3-16A): complex_mult_iq.v backpressure bug fixed. This module is affected indirectly through u_frac_corr (frac_cfo_corrector_top uses complex_mult_iq). The stalled frac_m_tvalid stream would have caused the extractor to wait indefinitely. Fix: can_accept = !m_axis_tvalid || m_axis_tready.
ISSUE-002 RESOLVED (P3-15D gate): 100-frame statistical test primary detection. TB AXI-S race: stimulus applied at same delta as posedge aclk, causing spurious starts. Fix: #1 delay in TB after @(posedge aclk). The 100-frame gate was critical for detecting this intermittent failure.
Concurrent start rationale: All three start pulses fire simultaneously. This is intentional. Sequential start (start frac, wait for frac_done, start extractor) would require additional FSM states and add dead cycles. The AXI-S interface guarantees no sample loss because ext and meyr wait for data that only arrives after thousands of cycles of frac corrector processing.
Sign convention for int_cfo_step_word: The negation is critical. Verified exhaustively across k_int = -4, -3, -2, -1, 0, +1, +2, +3, +4 in XIP-004. A sign error would cause the integer correction to double the offset instead of canceling it — the symptom would be that output IQ after integer correction has a 2k CFO instead of 0.

Expected Signals at Each Debug Point

  • At frac_frac_phase_valid=1: frame_index should be a valid buffer offset (0..4095); frac_phase should be a small Q1.15 value (|frac_phase| < 0x0100 for low-CFO signals).
  • At meyr_done=1: meyr_int_cfo should equal k_int (known injected offset in bins); int_cfo_step_word_r should equal (-k_int) << 24.
  • done pulse: should appear 1 cycle after int_cfo_valid_r; busy should deassert in the same cycle as done.

Reset Sequence

  1. Apply aresetn=0 (≥8 cycles); verify ILA shows state=S_IDLE, busy=0, error=0.
  2. Release aresetn=1; wrapper will deliver start pulse after enable is set.
  3. Confirm all three start registers (frac/ext/meyr_start_r) pulse simultaneously.
  4. Monitor frac_m_tvalid: expect first valid approximately 1,500–3,000 cycles after start_r.
  5. After frac_frac_phase_valid: read via AXI-Lite registers 0x1C (frame_index), 0x20 (peak_lag), 0x2C (frac_phase). Compare to C reference.
  6. After meyr_done: read 0x3C (INT_CFO_EST) via AXI-Lite. Compare to expected NCO step word.

Hardware Risks

  • CORDIC timing: 15-stage pipeline can be a critical path; verify positive timing slack on all CORDIC chain registers.
  • Xilinx FFT IP: must configure forward transform, correct scaling schedule, and s_axis_config handshake before data input. Incorrect IP configuration will produce wrong frequency-domain output and wrong meyr_int_cfo.
  • Error recovery: after frac_frame_error, sub-modules are in partial state. Always issue soft_reset before retrying after an error indication.

17 Debug Checklist

  1. Verify state=S_IDLE, busy=0, done=0, error=0 after reset.
  2. Confirm start pulse is exactly 1 cycle from wrapper; not asserted while busy=1.
  3. Verify frac_start_r, ext_start_r, meyr_start_r all asserted in the same ILA sample.
  4. Confirm s_axis_tready reflects frac corrector internal state; no samples lost at input.
  5. Count frac_m_tvalid beats: must equal 576 (FRAME_LEN) before frac_m_tlast.
  6. Verify frac_frac_phase_valid is exactly 1 cycle wide; read frame_index and frac_phase values.
  7. Compare frame_index, peak_lag, frac_phase to C reference synchronization() output for same input frame.
  8. Test error path: inject all-zero frame; confirm error=1 after done; verify soft_reset required to restart.
  9. Verify meyr_done is exactly 1 cycle; confirm int_cfo_valid_r fires 1 cycle after meyr_done (registered).
  10. Cross-check int_cfo_step_word_r = (-k_int) << 24 for all 9 k_int test cases.
  11. Verify done is exactly 1 cycle; busy deasserts same cycle as done asserts.
  12. Run XIP-004 gate (Vivado xsim) before FPGA programming to confirm real FFT IP integration is correct.

18 Review Notes

Non-Obvious Design Decisions

  • OUTPUT_SAMPLES = FRAME_LEN = 576 override: The default of frac_cfo_frame_corrector_top is NSC+CP_LEN=288. This module overrides it to 576 (two full OFDM symbols) so both PSS at offset 32 and SSS at offset 320 are in the output stream. Without this, the extractor would never see the SSS symbol. The parameter comment in the RTL says "both PSS and SSS symbols are included in the corrected output stream" for this exact reason.
  • Simultaneous start design: All three starts fire in the same cycle. The extractor and Meyr modules enter wait states immediately. This avoids complex start-confirmation FSM states and dead cycles. The correctness guarantee is the AXI-S data dependency: extractor cannot consume samples until frac corrector produces them (thousands of cycles later).
  • int_cfo_step_word = (-int_cfo_ext) << 24: The formula encodes the complete integer CFO to NCO step conversion. Each FFT bin corresponds to 1/NSC of the sample rate. The 32-bit NCO step for 1 bin = 232/NSC = 224. Negation is required because the NCO must counter-rotate to cancel the measured offset.
  • frac_frame_error priority over meyr_done: In the S_RUN case, frac_frame_error is checked first in the if/else chain. If the frame detector fails, the Meyr algorithm (which may complete later) is irrelevant and its result is discarded. This ordering prevents a race where both conditions are simultaneously true.
  • negedge aresetn in FSM: Using negedge in simulation ensures asynchronous clear behavior matches synthesis intent. Some simulation tools have delta-cycle issues with posedge-triggered synchronous reset where the reset deasserts and a data transition occurs in the same simulation step.

Open Items for Future Engineers

  • busy outputs from u_frac_corr, u_extractor, u_meyr_fft are all unconnected (()). Consider routing these to additional debug outputs to allow finer pipeline stage monitoring on FPGA.
  • Error recovery: no partial reset mechanism. Consider adding per-sub-module start/reset capability to avoid requiring full aresetn toggle for error recovery.
  • The frac_frame_error + meyr_done simultaneous assertion edge case is handled by priority but never explicitly tested. Consider adding a test case for this scenario.
