The PS (ARM processor) sends raw IQ samples via AXI-Stream DMA to s_axis. After synchronization and integer CFO correction the wrapper emits corrected IQ back to the PS via m_axis — a single-slot OFDM frame per replay cycle.

Clock Domain & Reset

Single clock domain: aclk. All registers synchronous to posedge aclk. Reset hierarchy:

  • aresetn — board-level active-low reset from PS. Drives AXI-Lite register bank directly.
  • dut_aresetn = aresetn && !soft_reset_r — drives all internal datapath. Soft reset allows PS to re-trigger synchronization without a full board reset.

The AXI-Lite register bank (u_regs) uses aresetn so it remains accessible during soft reset.

7 Operation

Reset and Startup

On aresetn=0 all registers clear. dut_aresetn = aresetn && !soft_reset_r gates all datapath sub-modules. The AXI-Lite register bank uses aresetn directly so it survives a soft reset and remains accessible to the PS. On release of reset, reset_done_w (rising edge of dut_aresetn) fires for one cycle, which arms start_armed_r=1 on the next clock.

Enable Gate

The register bit enable (CONTROL register 0x04, bit 0) must be set before any data flows. When enable=0: s_axis_tready=0 (stalls upstream DMA), m_axis_tvalid=0 (no output emitted). The PS must write 0x1 to CONTROL after reset release to begin operation.

Bypass Mode

When bypass_enable=1 (DEBUG_CONTROL 0x4C bit 0): s_axis_tdata routes directly to m_axis_tdata and s_axis_tvalid to m_axis_tvalid. s_axis_tready = m_axis_tready. The DUT and replay buffer receive no data. Useful for DMA chain bring-up before the sync algorithm is active.

Normal Datapath

When enable=1 and bypass_enable=0, incoming IQ samples are accepted by u_dut (phase3_sync_top) which implements the full synchronization() algorithm. Simultaneously, the frac-corrected IQ stream (tapped as dut_frac_m_* between the frac corrector and the PSS/SSS extractor inside u_dut) feeds u_replay_buf. The replay buffer captures the first FRAME_LEN=576 samples.

Start/Done/Replay State Machine

The wrapper contains an explicit start-arm state machine (start_armed_r, start_r):

  1. Reset release: reset_done_w fires; start_armed_r set to 1.
  2. start fires: when int_enable && start_armed_r && !dut_busy → start_r=1 (one-cycle pulse), start_armed_r=0. Starts u_dut processing.
  3. Algorithm running: u_dut busy; replay buffer capturing frac-corrected IQ. No re-arm.
  4. int_cfo_valid: u_dut asserts dut_int_cfo_valid with step word. NCO loaded, warmup counter started.
  5. NCO warmup: int_nco_wu_cnt counts down from NCO_WU_CYCLES=16 to 0. NCO enable is forced high during warmup to flush the CORDIC pipeline. replay_start_w fires when int_nco_wu_cnt==1 (last warmup edge), so the first replay sample is presented exactly when sin/cos output is valid.
  6. Replay: u_replay_buf drives replay IQ through u_int_rot (complex_rotator applying integer CFO correction) to m_axis. TLAST is generated by the out_frame_cnt counter at beat int_frame_len-1.
  7. Replay done: replay_done asserts; replay buffer cleared on next cycle; start_armed_r=1 (re-arm for next frame). Cycle repeats.
  8. Error path: if dut_done && dut_error, start_armed_r=0; the PS must write soft_reset_pulse to CONTROL to restart.

Integer CFO NCO Sequencing

When dut_int_cfo_valid fires: the NCO receives load_step and phase_reset simultaneously. The int_nco_enable signal is int_nco_wu_active || !int_nco_sincos_valid || (replay_rd_valid & replay_rd_ready), which ensures the NCO clock-enables for the full warmup period regardless of replay state. The +1 term in NCO_WU_CYCLES accounts for the output register in nco_phase_gen (sin_out_r) which adds one extra pipeline cycle beyond the CORDIC LATENCY stages.

INT_CFO_APPLIED Sticky Flag

int_cfo_applied_r is set (sticky) on the first cycle replay_busy asserts. It is cleared only by dut_aresetn. The PS reads this at register 0x44 to confirm integer correction was applied to the output stream.

TLAST Generation

A 12-bit output sample counter out_frame_cnt increments on each m_hs (output handshake). TLAST fires when out_frame_cnt ≥ int_frame_len - 1 or when force_tlast_latch is set. The counter resets on the same cycle TLAST fires. int_frame_len is programmable via register 0x0C (default 576). tlast_count (register 0x50) accumulates the number of TLAST events seen since last reset.

Error Detection

  • FRAME_LEN_MISMATCH (bit 0): tlast arrives at beat other than int_frame_len-1 on s_axis.
  • TLAST_TIMEOUT (bit 1): 8190 m_hs beats without a TLAST event on m_axis.
  • RESET_WHILE_ACTIVE (bit 2): dut_aresetn deasserts while output_count > 0.
  • STALL_TIMEOUT (bit 3): m_axis_tvalid held high with tready=0 for 254 consecutive cycles.

All flags are sticky write-1-to-clear (W1C) via register 0x54. They capture error conditions without interrupting operation.

The integer CFO correction this wrapper applies is the second apply_carrier_freq_offset() call (receiver.c:307), where the C reference passes f = −kint·Fs/NSC so that the output is corrected[n] = raw[n]·e −j2πf n/Fs:

m_axis[n] = replay[n]·e −j2πf n/Fs,   f = −kint·FsNSC

The int_cfo_step_word = -int_cfo_est << INT_CFO_SHIFT computed in phase3_sync_top is the NCO step word for integer correction, equivalent to the C-reference negated frequency offset −kint scaled for the 32-bit phase accumulator (kint = the return of carrierFreqOffsetEstMeyr(), receiver.c:535).

No direct C-reference for the wrapper's outer shell: the AXI4-Lite register bank, AXI-Stream boundary, replay buffer, start-arm FSM, NCO warmup sequencing, and TLAST/error monitors are board-integration infrastructure for hosting the synchronization() call tree — they have no algorithmic counterpart in ref/*.c.

15 Known Issues / Lessons Learned

ISSUE-001 RESOLVED (P3-16A): complex_mult_iq.v backpressure bug. Root cause: can_accept was incorrectly set to !m_axis_tvalid (blocked when output was valid even if downstream was ready). Fix: can_accept = !m_axis_tvalid || m_axis_tready. Lesson: AXI-S flow control must always include the downstream ready signal in the acceptance condition — "output valid but downstream ready" must still accept new input.
ISSUE-002 RESOLVED (TB AXI-S race): Phase 3 testbench D3 had a simulation race: stimulus was applied at the same delta time as posedge aclk in the TB stimulus loop. Fix: add #1 delay after @(posedge aclk) before asserting tvalid/tdata. Lesson: never drive AXI-S signals in the same delta as the sampling clock edge in a clocked testbench.
XIP-004 lesson: when integrating real Xilinx FFT IP (XFft), the IP requires the configuration channel (s_axis_config_*) to be fully handshaked before data arrives. Stub-based simulations may not expose this protocol requirement. Always run at least one test with the real IP before declaring gate PASS.
Re-arm timing (P3-14B design decision): The start re-arm was moved from dut_done to replay_done. This adds latency between algorithm completion and the next capture start, but is essential to prevent buffer corruption. The frac-corrected IQ side-channel feeds the replay buffer write port; if a new capture started during replay, new samples would overwrite BRAM locations the replay read port is actively reading.
TODO (registered, not a blocking issue): PSS_DONE (0x30) and SSS_DONE (0x34) registers are not yet wired to outputs from phase3_sync_top; reads return 0. INT_CFO_INDEX (0x40) always returns 0. These are observability gaps that do not affect functional correctness — the algorithm output (int_cfo_word) is correctly forwarded through the NCO chain.

Reset Sequence (numbered steps)

  1. Assert aresetn=0 for ≥8 clock cycles to ensure all registers clear.
  2. Release aresetn=1. Verify RESET_STATUS[0] (RESET_DONE) sets within 2 cycles.
  3. Write 0x1 to CONTROL (0x04) to set enable=1. Verify STATUS[0]=busy transitions to 1 as algorithm starts.
  4. Apply IQ sample stream to s_axis. Monitor INPUT_COUNT incrementing.
  5. Poll INT_CFO_VALID (0x38). When it reads 1: this read atomically snapshots all 5 result registers. Read FRAME_START_INDEX, PEAK_INDEX, SLOT_START_INDEX, FRAC_CFO_PHASE, INT_CFO_EST.
  6. Verify INT_CFO_APPLIED (0x44) = 1, confirming integer correction replay is active.
  7. Monitor TLAST_COUNT (0x50) incrementing; each increment = one 576-sample corrected frame sent to DMA.
  8. Check ERROR_FLAGS (0x54) = 0x0 for no errors.

AXI-Lite Register Access Notes

  • Snapshot protocol: reading INT_CFO_VALID (0x38) while the latch is set simultaneously clears the latch AND freezes all 5 result registers (frame_start_index, peak_index, slot_start_index, frac_cfo_phase, int_cfo_est) into shadow registers. This prevents a race between live latch updates from a second frame and the PS reading stale values.
  • Writes to read-only registers return OKAY but have no effect.
  • Unmapped address reads return SLVERR with rdata=0x0.

Hardware Risks

  • BRAM initialization: ensure BUF_AW=12 BRAM contents are zero after bitstream load; random BRAM contents may cause false frame detection on first run.
  • NCO phase alignment: if hardware is restarted mid-replay, the NCO accumulator may have stale state. Always use soft_reset (register 0x04 bit 1) to reset dut_aresetn between experiments.
  • DMA burst sizing: PS DMA engine must be configured with burst length matching FRAME_LEN (576 samples = 2304 bytes per burst) to avoid TLAST mismatch errors.

17 Debug Checklist

  1. Verify aresetn asserts and releases cleanly (no glitches on ILA); confirm RESET_STATUS[0] transitions.
  2. Confirm CONTROL register write: read back 0x04 = 0x1 after writing enable.
  3. Check INPUT_COUNT incrementing at expected rate; if stuck, check s_axis_tvalid from DMA and s_axis_tready from wrapper.
  4. Verify bypass mode before enabling DUT: write 0x1 to DEBUG_CONTROL (0x4C), check m_axis mirrors s_axis sample-for-sample.
  5. Confirm frac CFO path via dbg_frac_m_* ILA probes; compare against C golden reference for same input frame.
  6. Verify INT_CFO_VALID pulse occurs after expected number of input samples (~10k cycles).
  7. Confirm NCO warmup: on ILA, int_nco_wu_cnt should count 16 down to 1, then replay_start_w pulses once.
  8. Verify INT_CFO_APPLIED = 1 after replay begins; check TLAST_COUNT increments with each replay.
  9. Confirm backpressure handling: hold m_axis_tready=0 for 10 cycles; verify STALL_TIMEOUT flag only sets after 254 cycles, not earlier.
  10. Check ERROR_FLAGS = 0 across 10 consecutive frames in ILA capture.
  11. Compare INT_CFO_EST (0x3C) against C-reference carrierFreqOffsetEstMeyr() result for same input data.
  12. Verify XIP-004 gate PASS in xsim before FPGA programming to confirm real IP behavior.

18 Review Notes

Non-Obvious Design Decisions

  • dut_aresetn vs aresetn split: The split between aresetn (AXI-Lite registers) and dut_aresetn (everything else) is intentional. A soft reset must not destroy the register bank contents, since the PS reads results from registers immediately after the algorithm completes. If both used the same reset, a soft reset would clear INT_CFO_EST before the PS could read it.
  • NCO_WU_CYCLES = CORDIC_LATENCY+1: The +1 is for the output register in nco_phase_gen (sin_out_r). Without this, the first replay sample would be multiplied by the sin/cos from the wrong NCO phase (one cycle behind the accumulator state). This is a subtle pipeline hazard that only manifests with careful waveform inspection.
  • Replay buffer feeds from frac-corrected stream, not raw s_axis: The replay buffer captures the frac-corrected IQ (from the dbg tap between frac_cfo_frame_corrector_top and pss_sss_symbol_extractor), not the raw input. This means the m_axis output has both frac and integer CFO corrections applied — the full C-reference apply_carrier_freq_offset() for frac, then again for integer.
  • Re-arm on replay_done not dut_done: There is a gap between dut_done (algorithm complete) and replay_done (576 samples played back). The wrapper deliberately does not start a new algorithm run during this window. A future engineer who "optimizes" this by re-arming on dut_done will introduce a capture/replay collision bug in the BRAM.
  • TLAST generation is counter-based, not from replay_done: m_axis_tlast is driven by out_frame_cnt, not by the replay buffer's rd_tlast signal. This allows the TLAST period to be decoupled from the exact replay length and adjusted via software (register 0x0C). In practice both should match (576 beats), but the counter provides robustness if the replay buffer count diverges.

Open Items for Future Engineers

  • Wire PSS_DONE (0x30), SSS_DONE (0x34), and INT_CFO_INDEX (0x40) registers to actual sub-module signals (currently tied to 0).
  • Consider adding a second replay capability: replay the integer-corrected output a second time after PS updates the NCO step word for fine-tuned correction.
  • BUF_AW=12 is larger than needed for FRAME_LEN=576. Reducing to BUF_AW=10 (1024 entries) saves 3 BRAM18K resources at the cost of tighter timing margin.
  • The STALL_TIMEOUT threshold (254 cycles) may be too aggressive for systems with deep DMA FIFOs. Consider making it a programmable register.
