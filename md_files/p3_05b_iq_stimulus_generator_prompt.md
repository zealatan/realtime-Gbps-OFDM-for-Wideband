## Interpretation

The frame_detector in golden_dump.c uses:
  wndLen=25, threshold=40000.0 (float energy per sample, averaged over 25)

The run_phase3_sync_sim.sh step-b runs golden_dump on the .f32 file.
Step-c converts .f32 → Q15 hex using a normalise-to[-1,1] function that
is WRONG for integer-scale float samples (clips everything to ±32767).
This must be fixed to do a direct int16 clamp.

Signal design:
  Two independent OFDM symbols with QPSK subcarriers, IFFT → CP prepend.
  CP is the last CP_LEN samples of the symbol time-domain vector.
  Scale so that max per-component float = TARGET_PEAK (set to 3000).
  Apply fractional CFO to entire frame.

The generator also runs the C-reference algorithms (frame_detector, auto_corr)
inline to produce deterministic expected values for the metadata JSON.

## Architecture Decisions

1. QPSK subcarriers (table: (±1±j)/√2) with numpy.fft.ifft for determinism.
2. Peak-normalization: scale so max(|I|, |Q|) over signal portion = TARGET_PEAK=3000.
   Guarantees energy/sample >> threshold=40000 and no int16 overflow.
3. Generator runs frame_detector and auto_corr in Python to compute exact
   expected indices (same algorithm as golden_dump.c).
4. run_phase3_sync_sim.sh: auto-generate if .f32 absent; fix Q15 conversion.

## Expected Signal Properties

  total samples       : 704  (PRE=64, SYM1=288, SYM2=288, POST=64)
  frame_start         : ≈40  (first above-threshold window; exact from algorithm)
  peakIndexAuto       : ≈24  (CP1 starts at offset 24 from frame_start≈40)
  slotStartIndex      : ≈64  (= peakIndexAuto + frame_start = PRE_ZEROS)
  fracfreqOffset      : ≈+0.05  (= eps_frac, derived analytically)
