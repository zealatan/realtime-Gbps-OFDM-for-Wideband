Full-chain now UNBLOCKED: the xfft 9.1 IP gates ran under xsim — P5-CONT-SMOKE (4032 identity), P5-CONT-NIGHTLY (k_int=+4 rot applied 100%), P5-AXI-COV, P5-D1-3WAY all PASS, giving phase3_sync_top (L3) and phase3_sync_axis_dma_wrapper (L4) real end-to-end evidence. L3/L4 continuous DATA-correctness ✓ (2026-06-24): P5-D continuous gate now 5/5 data-correct per case (was 0/5) + STAGE1 63/63 + P5-CONT-SMOKE bit-exact (D_rot=0) — this caught+fixed a real RTL bug: moving_avg_optimized.v sliding-window RAM was not cleared on reset, so the CP-autocorr carried a constant offset that corrupted fractional CFO on continuous slot 2+. The previous SMOKE/NIGHTLY count-only check (sample COUNT, not data) MISSED it; the window-fill guard fix makes all 5 cases bit-exact. L5 bit-exact M_AXIS regression still open: P5-CORRECTED FAILs at 60% bit-exact — but the RTL CFO rotation is proven correct (mout is a magnitude-exact k=4 NCO rotation of frac, |ratio|=1.000, +5.625°/sample); the residual is a frac/mout capture beat-gap alignment limit in the python comparator, not an RTL bug.
