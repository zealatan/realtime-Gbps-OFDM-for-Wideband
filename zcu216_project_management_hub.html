Maintenance Rules

Rule 1: Do not put daily logs, temporary bugs, or Claude-generated attempts into the main verification plan. Put them into status, KPI, coverage, or issue dashboards.
Rule 2: Every issue must have an ID, symptom, suspected root cause, evidence, owner/tool, next action, and close condition.
Rule 3: Every promotion must pass through the same gate order: PS-only RFDC → IQ sign/bin check → PL BYPASS → DDR TX/RX → SYNC DUT insertion → RF loopback stability.
Rule 4: Keep one vector ID across RTL simulation, FPGA DDR test, and RFDC loopback capture so mismatches can be traced without ambiguity.
